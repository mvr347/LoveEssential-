# Love Integration — аддон DeluxeCombat

Отдельный нативный аддон DeluxeCombat для Paper/Purpur 26.2+ / Java 25.
Он не заменяет DeluxeCombat и не запускает вторую систему наказаний или дропов.
Исходники находятся в репозитории LoveEssential, итоговый JAR независим от его JAR.

## Установка

1. Установить LoveCore и DeluxeCombat. LoveEssential, LoveDuels и ReviveMe — по необходимости.
2. Поместить **LoveDeluxeCombatAddon-2.0.0-SNAPSHOT.jar** в
   `plugins/DeluxeCombat/addons/`, рядом с другими аддонами DeluxeCombat.
   Это не Bukkit-плагин: в обычную папку `plugins/` его класть не нужно.
3. Полностью перезапустить сервер. Включить аддон **Love Integration** в менеджере
   аддонов DeluxeCombat, если автоматическая загрузка отключена.
4. Проверить сообщение `[Love Integration] Аддон подключён` в консоли.
   Настройки создаются в `plugins/DeluxeCombat/addons/LoveIntegration.yml`.
   После их изменения перезагрузить аддон штатным менеджером либо перезапустить сервер.

Используется официальный DeluxeCombat API, зафиксированный на коммите
[`5fdc2c029f`](https://github.com/timderspieler/DeluxeCombat-API/tree/5fdc2c029f).
Нужны методы `getRemainingCombatTimeMillis`, `tag`, `untag`, `hasProtection`,
`hasPvPEnabled` и нативный загрузчик `Addon`. Старые версии без этих методов
не поддерживаются: ошибка подключения записывается в консоль. JAR DeluxeCombat
и его реализация в артефакт не включаются.

## Поведение

- **LoveCore:** CombatState читает реальные метку и остаток времени DeluxeCombat.
  После снятия метки не добавляются лишние 15 секунд из старого metadata-fallback.
  Потребители этого сервиса, включая LoveEssential и LoveTweaks, получают один ответ.
  Другие плагины должны действительно использовать CombatState: чтение собственных
  таймеров или произвольных metadata аддон не перехватывает.
- **Войны/осады:** явные `mark(..., "siege"/"raid"/...)` продолжают действовать
  независимо от окончания метки DeluxeCombat. Старые автоматические `pvp` и
  `DeluxeCombat`-метки исходной службы не подмешиваются обратно. Явный `clear`
  снимает также метку DeluxeCombat на основном потоке.
- **LoveEssential Revive / ReviveMe:** после подтверждённого падения от PvP аддон
  ставит метку через API DeluxeCombat жертве и атакующему. Состояние проверяется
  на следующем тике после события; отменённое или не состоявшееся падение метки
  не создаёт. Учитываются стрелы и другие снаряды игрока. Более длинная метка
  не сокращается. Защита и отключённый PvP DeluxeCombat уважаются.
- **Выход лежащего:** обычное боевое наказание DeluxeCombat не отменяется.
  Поднятие также не снимает боевую метку автоматически. Аддон сам не убивает
  игрока, не создаёт NPC-заменителей и не выбрасывает предметы.
- **LoveDuels:** участникам активного матча запрещено падать в Revive вместо
  завершения дуэли. Метки DeluxeCombat у участников снимаются при синхронизации;
  его CombatlogEvent для участника отменяется даже до следующей синхронизации.
  Обычный урон внутри дуэли не отменяется. Используется публичная цепочка
  `getDuelManager().getMatchManager().isInMatch(UUID)`.
- **LoveAuth / vanish:** через AuthOracle и PresenceOracle блокируется PvP с
  неавторизованными и скрытыми игроками; для них снимается метка и отменяется
  CombatlogEvent. AFK сам по себе не даёт иммунитет.
- **LoveHunt и обработчики смерти:** при смерти по таймеру встроенного Revive
  восстанавливается исходный онлайн-атакующий через Bukkit `setKiller`, если
  более свежего убийцы нет. Это происходит до обычных обработчиков смерти.
  Для самоубийства, команды и выхода убийца искусственно не назначается;
  награды/трофеи аддон сам не выдаёт. Для таймерной смерти ReviveMe такая
  атрибуция пока не реализована.
- **Два Revive:** если ReviveMe установлен и включён, встроенное падение
  LoveEssential отменяется по умолчанию. Аддон не меняет конфиги других плагинов.
  Согласовать глобальный выбор провайдера LoveCore и LoveTweaks нужно отдельно.

## Настройки

```yaml
sync-period-ticks: 1 # Частота синхронизации, 1–20 тиков; по умолчанию каждый тик.
downed:
  tag-seconds: 15 # Длительность новой метки после падения; 0 отключает её постановку.
  tag-attacker: true # Также пометить атакующего.
duels:
  exclude-from-deluxecombat: true # Дуэль управляет собственным завершением/выходом.
  prevent-downed: true # Запретить падение в активной дуэли.
protection:
  auth: true
  vanish: true
revive:
  prefer-reviveme-if-installed: true
```

Это отдельное время **новой** метки при падении, а не чтение приватного конфига
DeluxeCombat. Если у вас бой длится 30 секунд, укажите `tag-seconds: 30`.
Синхронизация до одного тика задержана намеренно: API читается после обработки
событий, а асинхронные потребители получают неизменяемый снимок. Bukkit и API
DeluxeCombat не вызываются из асинхронных запросов CombatState. Синхронизация
линейна по количеству игроков в сети; отложенная задача на каждый удар не создаётся.

## Проверка

```sh
./mvnw -B -pl addons/deluxecombat -am verify
```

Тесты используют MockBukkit и тестовую реализацию официального API: метки и их
снятие, независимые осады, отмена падения, дуэли, авторизация, атрибуция таймерной
смерти, выгрузка и устаревшие задачи. Это не запуск коммерческого DeluxeCombat.

**Перед установкой на основной сервер:** на копии Paper/Purpur проверить реальную
версию DeluxeCombat и ReviveMe, выход лежащего с обоими вариантами keepInventory,
обходы телепортации, награды LoveHunt и порядок выдачи/дропа предметов. Аддон не
исправляет внутренние snapshot/drop-механизмы ReviveMe/LoveTweaks и не подтверждает
отсутствие дублирования предметов без этих испытаний.
