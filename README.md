# LoveEssential

**Модульный плагин для Paper / Purpur 26.2+ на Java 25:** NPC с мастером создания, маршрутами и диалогами; TAB; дома и телепортация; личные сообщения; никнеймы с цветами и градиентами; просмотр инвентаря и досье игроков. Плагин использует LoveCore и подключает сервисы экосистемы Love.

[![Build and test](https://github.com/mvr347/LoveEssential-/actions/workflows/build.yml/badge.svg)](https://github.com/mvr347/LoveEssential-/actions/workflows/build.yml)

**Документация:** [новые папки, GUI и редакторы TAB/scoreboard](docs/MODULAR_CONFIGURATION.md) · [миры, состояния и оформление меню](docs/MODULE_ACCESS_AND_GUI.md) · [порталы](docs/PORTALS.md) · [миры, сценарии, диалоги и scoreboard](docs/WORLDS_AND_AUTOMATION.md) · [крафты и стартовый набор](docs/CUSTOM_CONTENT.md) · [все команды и алиасы](docs/COMMANDS.md) · [все плейсхолдеры](docs/PLACEHOLDERS.md) · [права доступа](docs/PERMISSIONS.md) · [руководство администратора](docs/ADMIN_GUIDE.md)

## Путевые столбы

Модуль `waystones`: деревянные указатели, каменные столбы, рунические обелиски и
предметы-модели ItemsAdder. ПКМ открывает выбор направлений с ценой, подготовкой
и задержкой. Создание: `/le waystone create`, редактор: `/le waystone edit`.
Общий каталог моделей: `/le waystone models` — встроенные варианты, четыре VoidCore-пресета
и свои модели ItemsAdder. Видимые номера повторно занимают свободные места, начиная с №1.
[Настройка, права, экономика и ограничения](docs/WAYSTONES.md).

| Личные сообщения | `/msg`, `/reply`, игнор-лист, отключение приёма сообщений и настройки через GUI |

| Инвентарь | Живой просмотр инвентаря онлайн-игрока и перенос предметов с отдельным правом на редактирование |

NPC работают на нативных сущностях Paper, включая MANNEQUIN со скином игрока. Для этого backend не нужны Citizens, ProtocolLib или PacketEvents.

## Установка

1. Подготовьте **Java 25** и **Paper / Purpur 26.2+**. API сборки: `26.2.build.100-stable`.
2. Установите совместимый [LoveCore](https://github.com/mvr347/LoveCore). Сборка использует API commit [`5a99cdb141`](https://github.com/mvr347/LoveCore/tree/5a99cdb1413be77d4b7a2dcbfedcc06f62d1c7ba).
3. Получите JAR из [GitHub Actions](https://github.com/mvr347/LoveEssential-/actions/workflows/build.yml): успешный запуск → артефакт `LoveEssential-Java25`. Выберите запуск для нужной ветки или PR.
4. Поместите `LoveEssential-2.0.0-SNAPSHOT.jar` в `plugins/` и перезапустите сервер.
5. Для настройки модулей откройте `/le` от администратора. Выдайте `loveessential.admin` или отдельные [права](docs/PERMISSIONS.md).

Для PlaceholderAPI-плейсхолдеров установите **PlaceholderAPI**: расширение `loveessential` регистрируется самим плагином. Дополнительная загрузка расширения через eCloud не требуется. TAB реализован внутри LoveEssential. `/le tab` открывает редактор шапки, подвала, групп, плейсхолдеров, сортировки и имён. Строки и цветовые коды находятся прямо в `modules/tab/tab.yml`.

## Настройки и данные

```text
plugins/LoveEssential/
├── config.yml          # Общие параметры
├── lang.yml            # Резервный источник старой локализации
├── modules/
│   ├── npc/
│   │   ├── npc.yml     # Настройки и тексты объектов
│   │   └── gui.yml     # Все меню, подписи, текстуры и оформление
│   ├── tab/
│   │   ├── tab.yml     # Строки, группы, плейсхолдеры и цвета TAB
│   │   └── gui.yml
│   ├── scoreboard/
│   │   ├── scoreboard.yml  # Именованные табло и условия показа
│   │   └── gui.yml
│   └── ...             # Такая же структура для каждого модуля
├── loveessential.db    # NPC, черновики, профили и состояния
├── backups/            # Резервные копии SQLite
└── exports/            # Экспорт NPC для переноса
```

Доступны 29 модулей: `npc`, `tab`, `home`, `spawn`, `vanish`, `afk`, `skin`, `sitride`, `utilities`, `nightskip`, `portal`, `hologram`, `traces`, `joinquit`, `motd`, `messages`, `inventory`, `profile`, `nickname`, `crafting`, `starter`, `worlds`, `scenarios`, `dialogs`, `scoreboard`, `revive`, `rtp`, `display`, `calamities`.

`/le module` открывает список: ЛКМ — настройки, ПКМ — включение/отключение. Состояние, заданное командой или GUI, сохраняется в SQLite и имеет приоритет над `enabled` в файле модуля. `/le reload` перечитывает конфиги и язык. Старый монолитный конфиг переносится с копией `config.yml.pre-modules.bak`; плоские файлы модулей — с копиями `*.yml.pre-folders.bak`. Пользовательские тексты и оформление сохраняются.

`/le backup` создаёт копию SQLite. Для полной резервной копии сохраняйте также локальные `messages` в файлах модулей, `config.yml` и `modules/`. Настройки и снимки профилей хранятся в SQLite; ванильный инвентарь сохраняет Minecraft. История личной переписки в базу не записывается.

## Интеграции

Обязательный LoveCore предоставляет авторизацию, кланы, репутацию, территорию, экономику, уведомления и статистику через зарегистрированные сервисы. LoveEssential использует LoveAuth, LoveClans, LoveBehavior, LoveClaims, LoveEconomy, LoveNotify и StatBus при наличии соответствующих провайдеров. LoveSubnames подключается через PlaceholderAPI; для LoveContracts и LoveShops есть действия открытия меню.

Сторонний чат может использовать Bukkit `displayName` или `%loveessential_nickname%`. API содержит отменяемое `PrivateMessageEvent` для фильтров личных сообщений; для LoveChat/LoveChatFilter нужен обработчик этого события. Наличие плагина в `softdepend` означает порядок загрузки, а доступные предметные интеграции перечислены в [руководстве](docs/ADMIN_GUIDE.md#интеграции-love).

## Сборка и API

```bash
./mvnw -B verify
```

Сборка требует JDK 25. Результат: `plugin/target/LoveEssential-2.0.0-SNAPSHOT.jar`; API: `api/target/loveessential-api-2.0.0-SNAPSHOT.jar`. GitHub Actions собирает плагин и запускает тесты на Java 25.

Хранилище использует SQLite, HikariCP и ограниченные очереди чтения/записи на virtual threads; кеши — Caffeine и ConcurrentHashMap. Bukkit-операции с миром и инвентарями выполняются на серверном потоке. Примеры API, NPC, маршрутов, диалогов и экспорта TAB находятся в [руководстве администратора](docs/ADMIN_GUIDE.md).

## Управление модулями и универсальные NPC

Главная панель `/le` предназначена только для настройки, включения и выключения модулей. Управление объектами открывается отдельно: `/le npc`, `/le portal`, `/le hologram`; личные меню — через `/le nick`, `/le profile`, `/le msg`.

У NPC нет профессии или категории. Внешность, движение, взгляд, действия и диалоги назначаются независимо; один NPC может сочетать несколько возможностей. Список показывает «Имя · №12»: ЛКМ сразу открывает редактор, ПКМ предлагает подтверждённое удаление. Нового NPC создают кнопкой в рабочей зоне. Мастер показывает объяснение каждого параметра; булевы значения и известные режимы подписаны по-русски. Список точек маршрута позволяет выбрать точку, перенести её, изменить ожидание/скорость/радиус, поменять порядок и удалить с подтверждением. В списке назначенных действий можно переставлять и удалять отдельные действия.

Числовые настройки модулей изменяются кнопками или точным вводом. Параметры TAB, bossbar и материалы карточек выбираются в GUI. В запросе ввода в чат указаны редактируемый параметр, пример и текущее значение; кнопка «ОТМЕНИТЬ ВВОД» возвращает в меню. Старая кнопка отмены не влияет на новый запрос.

Взгляд NPC работает во время паузы движения после клика и в предпросмотре. В `modules/npc/npc.yml` раздел `tracking` задаёт `update-ticks` (1–20; по умолчанию 2) и `max-turn-degrees` (1–180; по умолчанию 30). Это поворот модели, без телепортации для слежения.

## Посадка, следы и голограммы

`/sit` учитывает поверхность ступеней, плит и ковров; доступна посадка по ПКМ пустой рукой. `/ride [игрок]` проверяет направление взгляда; носитель снимает пассажира командой `/сбросить` или ударом. `/lay` (`/лежать`) позволяет лечь. `/hat` меняет предмет в руке и шлем местами. `/traces` сохраняет личный выбор следов. `/sethome` отвечает «Точка дома установлена.»; `/home` телепортирует без кнопки возврата. ЛС поддерживают кликабельный ответ.

`/hologram` открывает редактор с автоматическим ID, текущими значениями строк, перестановкой, страницами по ПКМ, фоном, предметами и отдельными плейсхолдерами для каждого зрителя. Для магазинов есть Bukkit-сервис `HologramService`. Добавлены `heal`, `feed`, `fly`, `speed`, `gamemode`, `repair` с отдельными правами. [Настройка и API](docs/COMFORT_AND_HOLOGRAMS.md).

## Профиль и приватность

`/profile [ник]` открывает профиль с безопасностью LoveAuth, персонализацией LoveSubnames, адаптациями LoveAdaptation и кнопкой репутации LoveBehavior `/rep`. `/profile settings` → «Активность и приватность» позволяет независимо скрывать весь профиль или только активность. Есть команды и плейсхолдеры для внешних меню. [Настройка, команды и примеры](docs/PLAYER_PROFILE.md).

Табло работает по [именованным табло с условиями показа](docs/SCOREBOARD.md) и API временных табло Love; личный каталог строк удалён. Профиль использует base64 головы из примеров, показывает сохранённые офлайн-данные и отдельное GUI статистики: `/profile stats`.

[Изменения GUI и миграция конфигурации схемы 6](docs/GUI_CONFIGURATION_V6.md): оформление рядом с экраном, фактическая навигация, сохранность шаблонов и откат при ошибке записи.

## Свои клан и пометка: /display

`/display` открывает шесть переключателей: свои клан и пометка отдельно для чата, TAB и имени над
головой. Отключённый элемент не виден никому, включая самого владельца; оформление других игроков
не меняется. Команды `/display clan chat off` и `/display пометки tab off` доступны обычным игрокам.
Выбор сохраняется в SQLite. LoveChat получает его через существующий сервис LoveCore — отдельного
обновления API не требуется. Старые флаги просмотра чужих подписей сохраняются в БД и плейсхолдерах
для совместимости, но больше не влияют на показ. Переключение `others` удалено; прежние флаги `own`
продолжают действовать. В форматах используются существующие теги `<clan>` и `<suffix>`.

## Выбранный NPC и действия в чате

`/npc sel` выбирает NPC под прицелом, `/npc sel <номер>` — по постоянному номеру. После выбора
`/npc delete`, `/npc edit`, `/npc info`, `/npc skin`, `/npc schedule`, `/npc enable`, `/npc disable`,
`/npc debug` и `/npc export` не требуют повторного номера. `/npc deselect` снимает выбор.
В сообщении о выборе и информации доступны кнопки действий с учётом прав. Удаление подтверждается
кнопкой в чате; запрос действует 60 секунд и не переносится на другого NPC после смены выбора.

[Аудит Revive / ReviveMe, DeluxeCombat и связанных Love-плагинов](docs/REVIVE_COMBAT_AUDIT.md):
подтверждённые ограничения, риски порядка обработчиков и сценарии проверки на сервере.

### Состояния игрока для Vesuvio

Для совместной работы с обновлённым Vesuvio добавлен отдельный Bukkit-сервис
`PlayerMechanicsService` в публичном API. Он возвращает неизменяемые состояния
посадки, лежания, езды, переноски, ранения, восстановления и God. Запрашивать
`snapshot(UUID)` нужно на главном потоке. После успешного изменения публикуется
`PlayerMechanicsChangeEvent`; обновление скина, скорости и полёта также сообщает
о коротком переходе. Отклонённые команды исключения не выдают.

Переносчик здорового игрока не получает постоянного освобождения от проверок.
Телепортации используют существующие события сервера. При выключении плагина
сервис снимается с регистрации, обработчики и задача наблюдения освобождаются.
Существующие API NPC, профилей и Revive остаются совместимыми. Для полной
интеграции обновите LoveEssential и Vesuvio вместе; настройки находятся в
`integrations.loveessential` конфигурации Vesuvio.


### Единое оформление Love

Профиль и настройки получили звуки, новые головы и общий формат подсказок. Взаимодействие со строкой табло: ЛКМ — заменить, ПКМ — удалить, Shift+ЛКМ — выше, Shift+ПКМ — ниже; варианты формата остаются в каталоге. Возврат ведёт в фактически открытое меню и сохраняет фильтр. Переключатель личных сообщений меняет приём ЛС сразу.

Бедствия используют реальное прошедшее время, включая отсутствие игроков и перезапуск: пауза `cooldown-days: 14` означает реальные сутки, `omen-minutes` и `types.<тип>.duration-minutes` — реальные минуты. Старые длительности в игровых сутках автоматически переводятся в прежнюю реальную длительность (20 минут за игровые сутки). По умолчанию событие длится 40–60 минут. Игровой наигрыш и счётчики болезней сохраняют прежнюю механику. Пропуск ночи плавно прокручивает время и будит игроков на рассвете.

Для обновления существующих конфигов установите актуальный LoveCore вместе с этой версией.
Однократная миграция сохраняет исходные YAML рядом с ними как `.pre-style-20261101.bak`.
После обновления можно менять оформление самостоятельно: перезапуск его не сбрасывает.

### Чатовый мастер портала

`/le portal wizard` (или `/портал мастер`) создаёт либо продолжает черновик.
Семь шагов: название → первый угол → противоположный угол → телепортация/команды →
частицы → условия → проверка и публикация. Все переходы выполняются кликабельными кнопками чата.
«Сохранить и выйти» оставляет шаг в SQLite; удаление черновика требует подтверждения.
Повторно проходя настроенную область, можно оставить уже выбранные точки.

Команду можно ввести с начальным `/`: мастер сохранит её без немедленного выполнения.
Корень должен быть разрешён в `modules/portal/portal.yml` в соответствующем списке
`allowed-player-commands` или `allowed-console-commands`. Например, для `/le rtp world`
нужен `le` в списке команд игрока. Права входящего игрока сохраняются.

Каталог содержит все 125 частиц Paper 26.2 с русскими названиями, категориями, поиском
и трёхсекундным предпросмотром только для администратора. Цвет действует у окрашиваемых
эффектов; для блоков и предметов используется аметистовый образец, переход пыли идёт к белому,
след и вибрация направляются к области портала. Гейзеры, эмиттеры и другие тяжёлые эффекты
ограничены восемью точками за обновление. Общие бюджеты остаются в `portal.yml`.

Все сообщения мастера и названия частиц находятся в `modules/portal/gui.yml`.
Расширенный редактор доступен на последнем шаге; `/le portal edit <id>` открывает его напрямую.
Обзор других мастеров и предложения: [docs/WIZARD_AUDIT.md](docs/WIZARD_AUDIT.md).

В категории scoreboard «Охота» добавлена строка билета с `%lovehunt_pass%`; фильтр получил
голову билета. Для новой строки требуется обновлённый LoveHunt с `pass`, `has_pass`, `pass_level`.
Остальные строки каталога не меняются; новая добавляется один раз с резервной копией.
Если администратор затем удалит билет из каталога, перезапуск его не восстановит.

Все строки категории «Охота» и строки с `%lovehunt_…%` доступны для выбора только владельцу
купленного билета (`%lovehunt_has_pass%` = `true`). Отключение требования билета в LoveHunt
не считается покупкой. Проверка действует при добавлении, замене, применении раскладок
и отображении: после потери билета строки скрываются, сохранённый выбор не удаляется.
При повторной покупке они снова показываются. В каталоге причина блокировки указана в лоре.
