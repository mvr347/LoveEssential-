# Аудит Revive, ReviveMe и боевых интеграций

Проверено 25 октября 2026 года по исходникам: LoveEssential `5bb3e89`, LoveCore
`49fc3a4`, LoveTweaks `b8ed137`, LoveDuels `bbfd5b5`, LoveHunt `152b0b4`.
Это анализ кода и тесты MockBukkit. Живой Paper/Purpur, коммерческие JAR
ReviveMe/DeluxeCombat и их серверные конфиги недоступны; совместимость конкретных
версий этих плагинов не подтверждена. Изменения данного PR не меняют правила боя.

После этого аудита добавлен отдельный [аддон Love Integration](../addons/deluxecombat/README.md).
При его установке часть перечисленных ниже ограничений обходится через CombatState,
события падения и проверку активной дуэли. Таблица описывает исходные реализации
на указанных коммитах; наличие аддона и совместимость его API нужно проверять отдельно.

## Подтверждённые особенности и ограничения

| Связка | Что происходит | Следствие |
| --- | --- | --- |
| LoveEssential + ReviveMe | Встроенный `Revive` реализует собственный `DownedOracle`, а не адаптер ReviveMe. Модуль по умолчанию выключен. Установка ReviveMe сама по себе его не отключает. | Выбирать один механизм падения. Не включать оба одновременно. Тест с плагином-заглушкой подтверждает отсутствие автоматического отключения, но не воспроизводит работу ReviveMe. |
| Revive + LoveCore | `Revive.damage` отменяет смертельный урон на `HIGHEST`; `CombatTracker.onDamage` слушает `MONITOR`, `ignoreCancelled=true`. | Первый смертельный PvP-удар, превратившийся в падение, не поступает в этот обработчик боевой метки. Регрессионный тест воспроизводит именно порядок Bukkit-событий. |
| DeluxeCombat + LoveCore | В `CombatTracker` внешнее состояние читается из настраиваемых metadata-ключей, по умолчанию `in_combat`. Прямого адаптера DeluxeCombat API здесь нет. | Нужно проверить, выставляет ли установленная версия DeluxeCombat эту метку. Снятие внешней метки не обязательно сразу снимает принятую LoveCore метку: действует собственный срок. |
| LoveEssential без CombatState | `LoveBridge.combat` при установленном LoveDuels либо LoveHunt консервативно возвращает бой для всех игроков. | Если служба LoveCore отсутствует, ограничения RTP/порталов/других действий могут срабатывать вне фактического боя. Это свойство fallback, а не обнаруженное поведение действующего сервера. |
| LoveTweaks + встроенный Revive | При провайдере `loveessential` модуль старых исправлений инвентаря ReviveMe не регистрирует обработчики. | Разделение предусмотрено правильно. Провайдер должен совпадать с реально выбранной механикой. После изменения глобального провайдера требуется перезагрузка настроек LoveTweaks: значение сохраняется в модуле. |
| Revive + LoveDuels | Оба обработчика смертельного урона имеют `HIGHEST` и пропускают отменённые события. Duel завершает матч отменой урона; Revive превращает его в падение. | Результат зависит от того, какой обработчик выполнится первым. Явной проверки дуэли через DownedOracle в просмотренном коде нет. Нужна отдельная договорённость об арене. |
| Revive + LoveHunt | Hunt хранит последнего атакующего 5 секунд, затем использует Bukkit killer. Падение по умолчанию длится 75 секунд; финальная смерть вызывается через `setHealth(0)`. | Сохранение исходного damage event не гарантирует определение убийцы через 75 секунд. Потеря награды пока не воспроизведена; нужен тест с реальной смертью и охотой. |

## Дополнительные проверки

- LoveAuth учитывается через `AuthOracle`; тотем и неуязвимость проверяются перед
  падением. Отмена урона `/god` на более раннем приоритете также пропускается.
- `restrictions.deny-in-combat` ограничивает помогающего, не лежащего игрока.
  По умолчанию выключено.
- `restrictions.clan-only` использует `ProfileOracle`. При отсутствии этой службы
  проверка разрешает помощь (`orElse(true)`), даже если ограничение включено.
  Проверить регистрацию службы при обязательном ограничении по клану.
- Проверки территорий идут через LoveBridge/TerritoryOracle, не через прямой API
  конкретного приват-плагина. Их включение не подтверждает наличие поставщика.
- Запрет команд лежащему не равен запрету телепортаций: в Revive нет обработчика
  `PlayerTeleportEvent`. Порталы, API и внешние телепортации требуют отдельного
  сценария проверки; наличие обхода здесь не утверждается.
- Окно обыска перепроверяет состояние, расстояние и доступ и закрывается при
  недействительной сессии. В этом PR «Закрыть» перенесено в последний слот.
- Принудительные дропы ReviveMe в LoveTweaks и наказание за combat-logout в
  DeluxeCombat нужно проверять вместе. Дублирование или потеря предметов по
  одному просмотру кода не подтверждены.

## Рекомендуемый порядок дальнейших исправлений

1. Явно выбрать провайдера падения и запретить одновременное включение двух
   реализаций; при конфликте показывать понятную диагностику.
2. Согласовать боевую метку и начало падения через публичный контракт LoveCore,
   с адаптером именно установленной версии DeluxeCombat.
3. Запретить падение внутри активной дуэли либо явно передать завершение матча
   дуэльному модулю. Не опираться на порядок загрузки слушателей.
4. Передавать исходного атакующего и причину окончательной смерти в Hunt через
   устойчивый контракт; не выдавать награду только по факту выхода из игры.
5. Применять общий DownedOracle к телепортам/порталам/свиткам и отдельно
   определить разрешённое поведение переносимого игрока.

## Матрица живых испытаний

- Первый смертельный удар, обычная серия ударов, добивание, таймер, самоубийство,
  успешное поднятие: проверить обе боевые метки и их время.
- Выход лежащего/переносящего игрока, перезапуск и смерть при каждом варианте
  keepInventory: пересчитать предметы до и после, включая обыск.
- Дуэль при обоих порядках регистрации слушателей; окончание матча ровно один раз.
- Охота: смерть спустя 1, 6 и 75 секунд после удара; награда и трофей ровно один раз.
- Телепорт порталом, свитком, командой администратора; урон и выход переносчика.
- Авторизация, клан, приват, vanish, тотем и god; недоступность служб LoveCore.
- Отдельно ReviveMe и встроенный Revive, затем проверка диагностики ошибочной
  конфигурации с двумя провайдерами.

Эти живые испытания ещё не выполнены. MockBukkit не заменяет проверку пакетов,
позы, инвентаря и взаимодействия коммерческих плагинов на сервере.
