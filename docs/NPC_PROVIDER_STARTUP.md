# Готовность NPC-провайдера

Провайдер `loveessential` регистрируется в ServicesManager LoveCore только после загрузки
определений и видимых номеров из SQLite. До этого отсутствие сервиса означает «ещё не готов»,
а не отсутствие конкретного NPC. Потребителям следует повторять подключение по
`ServiceRegisterEvent` и откладывать стартовое предупреждение; пустой адаптер заранее не публикуется.

`byKey()` принимает постоянный ID и видимый номер. Возвращённый `NpcHandle.key()` всегда
канонический постоянный ID; именно его следует сохранять в привязках. Удаление по номеру
работает с тем же ID, включая скрытие, очередь сохранений и голограмму.

Оптимистическое представление необходимо лишь до завершения сохранения. После успеха
и ошибки оно освобождается, поэтому удалённый через основной API NPC не остаётся
«призраком» в интеграциях и не исчезает неожиданно только после следующего перезапуска.
Уже отсутствующий `ext-...` нельзя считать временно загружающимся после регистрации
готового провайдера: потребитель сохраняет свою запись и предлагает явную перепривязку.
