# Скины и оформление статистики

`/skin <имя>` получает подписанные текстуры реального аккаунта Mojang по имени.
Серверный кэш профилей офлайн-игроков не используется как источник выбранного скина.
UUID и имя самого игрока сохраняются; модель slim и подпись текстуры передаются целиком.

Повторные запросы одного имени используют кэш на десять минут. HTTP 429 включает
общую паузу 60–600 секунд с учётом Retry-After. Уже сохранённые скины продолжают
применяться при входе без HTTP. Ошибки сети, HTML вместо профиля и неподписанные
ответы не заменяют текущий скин. Запоздавший ответ прежнего запроса или загрузка
при входе не должны заменять более свежий выбор.

Рекомендуется обновить LoveChat вместе с LoveEssential: идентификатор головы
в чате теперь зависит от текстуры, чтобы клиент не использовал прежний кэш.
LoveClaims и LoveChat создают головы из доступных текстур без запросов пустых
офлайн-профилей. Другие плагины, вызывающие обновление профилей, могут продолжать
делать собственные запросы к Mojang.

## Меню статистики

В `modules/profile/gui.yml` заголовок `menus.profile-menu-statistics.title`
по умолчанию содержит `<white>%img_offset_-8%%img_stats_menu%`.
Без ItemsAdder или зарегистрированного изображения используется `fallback-title`.
В ресурспаке должно быть изображение `stats_menu` (для другого пространства имён
укажите, например, `%img_voidcore:stats_menu%`). Старый стандартный текстовый заголовок
мигрирует автоматически с резервной копией; пользовательские заголовки сохраняются.

## Проверка на сервере

Сменить скин при двух наблюдателях: сравнить вид от третьего лица, TAB, чат и профиль,
затем переподключиться. Проверить обычный и slim-скин. При HTTP 429 текущая текстура
должна сохраняться; повторные попытки в период паузы не должны посылать HTTP-запросы.
Открыть статистику с загруженным ресурспаком и без ItemsAdder: рисунок либо текстовый
заголовок, без необработанных `%img_...%`.

Полупрозрачность сама по себе не доказывает ошибку PNG или скина. LoveAuth использует
временную невидимость в limbo: обновление LoveAuth сохраняет её исходное значение
в PDC игрока и восстанавливает даже при потере памяти плагина. Ранее сохранённая
невидимость без такой отметки требует отдельной проверки; чужие эффекты и vanish
автоматически не снимаются.

Для старых случаев: `/loveauthadmin visibility <игрок>` показывает состояние.
После проверки администратор может выполнить `/loveauthadmin visibility <игрок> repair`.
Команда отказывает при незавершённой авторизации, активном зелье невидимости, vanish
зарегистрированного провайдера/метаданных или режиме наблюдения. Без `repair` ничего
не меняется. Прочие сторонние механики невидимости нужно проверить перед ремонтом.
