# Папки модулей, GUI и оформление TAB/scoreboard

[Главная](../README.md) · [Правила доступа](MODULE_ACCESS_AND_GUI.md) · [Профиль](PLAYER_PROFILE.md)

## Файлы и миграция

Каждый модуль хранится в отдельной папке:

```text
modules/profile/profile.yml
modules/profile/gui.yml
modules/tab/tab.yml
modules/tab/gui.yml
modules/scoreboard/scoreboard.yml
modules/scoreboard/gui.yml
```

`<имя>.yml` содержит механику, ограничения и локальные тексты содержимого; `gui.yml` — меню, их подписи, текстуры, рамки и навигацию. Файлы заполнены текущими шаблонами: имена игроков и динамические показатели остаются переменными. Поддерживаются MiniMessage, RGB и плейсхолдеры. Корневой `config.yml` содержит общие параметры хранилища и версию схемы.

Плоские `modules/<имя>.yml` автоматически переносятся. Их точные исходники сохраняются рядом как `<имя>.yml.pre-folders.bak`, затем старый рабочий файл удаляется. Существующие новые файлы имеют приоритет. Неправильный YAML отклоняется до замены активных настроек. Старые тексты `lang.yml` переносятся в соответствующие локальные секции; сам файл сохраняется как резервный источник. Новые установки не получают второй полный набор GUI-текстов в корне.

После ручного редактирования выполните `/le reload`. Настройки включения модулей и выбор игроков по-прежнему сохраняются в SQLite. Для резервной копии сохраняйте базу и папку modules вместе.

## GUI

Основные разделы `gui.yml`:

| Раздел | Назначение |
| --- | --- |
| texts | Настоящие тексты с цветовыми кодами и переменными; изменение сразу влияет на меню после reload |
| menus | Текущие ID меню, заголовки, рабочие размеры и индивидуальные кнопки |
| buttons | Общие стили кнопок модуля по их ID; title/texture/lore могут заменить оформление |
| textures | Base64 головы карточек профиля |
| frame.material | Цвет стеклянной рамки |
| navigation.back / close | Текстуры навигации |

Пример фрагмента `modules/profile/gui.yml`:

```yaml
menus:
  profile-menu-title:
    size: 27
    title: '<gold>Профиль <white><player>'
    buttons:
      '12':
        slot: 12
        enabled: true
        title: '<gold>Мои настройки'
        lore:
          - '<gray>Чат, уведомления и приватность'
          - '<green>ЛКМ — открыть'
texts:
  profile-menu:
    settings: '<gold>Настройки'
frame:
  material: GRAY_STAINED_GLASS_PANE
```

Заголовок и lore можно задавать прямо через `title` и `lore`, либо использовать `title-key` и `lore-key`, указывающие на локальные texts. Кнопки переносятся вместе с действиями; изменение оформления не меняет права. Пустая texture наследует текущую текстуру. Для динамических списков пустые title-key/lore-key сохраняют вычисляемое содержимое строки. Общие административные подписи и окна настройки находятся в `modules/npc/gui.yml`; собственные экраны — в файле своего модуля.

Меню NPC, включая мастер и выборы условий/действий, поддерживают ту же систему оформления. Native Paper-диалоги получают тексты из локальных texts. Рабочая геометрия специализированных редакторов сохраняется: инвентарь, сетка крафта и восемь соседних слотов scoreboard имеют свои функции. Изменение косметики не создаёт новые команды или действия.

## TAB

`/le tab` открывает редактор. Можно добавлять, изменять, перемещать и удалять отдельные строки шапки/подвала и боковой панели TAB; создавать и удалять группы; редактировать сортировку, плейсхолдеры и имена над игроками. «Все параметры модуля» открывает остальные параметры, включая objectives и bossbar.

Все шаблоны находятся прямо в `modules/tab/tab.yml`:

```yaml
header-footer:
  enabled: true
  header:
    - '<gold>Моё королевство'
    - '<gray>В сети: <white><placeholder:online>'
  footer:
    - '<gray>Добро пожаловать, <white><player>'
placeholders:
  online: '%server_online%'
  rank: '<gold>Страж'
groups:
  guards:
    priority: 10
    permission: ''
    players: [Ada123]
    worlds: [world]
    name: '<white><player>'
    prefix: '<placeholder:rank> '
    suffix: ' <gray>| <clan>'
```

Меньший priority побеждает. Пустые players/worlds не ограничивают группу. В players допустимы настоящие имена без учёта регистра и UUID. Непустое permission проверяется дополнительно. Удалённые группы и плейсхолдеры не восстанавливаются из стандартного конфига.

`<placeholder:id>` вставляет локальный шаблон, `%identifier%` — PlaceholderAPI; `<nickname>`, `<clan>`, `<world>` и другие теги LoveEssential работают напрямую. Вложенность локальных шаблонов ограничена; удалённая ссылка даёт пустую вставку. Сортировка: `group`, `name`, `number:плейсхолдер`, `number-desc:плейсхолдер`.

Для отдельных миров и пользователей доступны секции worlds и users (UUID) с name/prefix/suffix/priority. Header/footer поддерживают profiles с permission, worlds и condition. Полная схема сетевого списка и фиктивных слотов NEZNAMY TAB не заявляется: это собственное оформление Paper.

## Scoreboard

`/le scoreboard` — личные восемь слотов. `/le scoreboard edit` — административный редактор каталога. В нём меняются заголовок, верх/низ, лимит, плейсхолдеры, их категории и условия. У каждой строки есть отдельный экран вариантов: название, полный шаблон, добавление, удаление и порядок. Цвета и символ `|` сохраняются буквально.

`modules/scoreboard/scoreboard.yml → catalog` заполняется при первом запуске текущим каталогом SQLite или импортом LoveTweaks. Пример:

```yaml
catalog:
  title: '<gold>Королевство'
  separator: ''
  bottom: '<gray>example.org'
  max: 8
  interval: 20
  disabled-worlds: []
  categories:
    general: '<gold>Общее'
  placeholders:
    player:
      name: '<gold>Игрок'
      category: general
      variants:
        - name: '<gold>Ник'
          template: '<gray>Игрок | <white><nickname>'
        - name: '<gold>С кланом'
          template: '<white><nickname> <gray>[<clan>]'
      lore: []
      requirement:
        placeholder: ''
        equals: ''
        reason: ''
  presets:
    basic:
      name: '<gold>Основное'
      lines:
        - id: player
          variant: 0
  default-preset: basic
```

Меняйте, добавляйте и удаляйте placeholders в файле или редакторе; до восьми вариантов на строку. Варианты нумеруются с нуля. Удалённые строки убираются из наборов, их личный выбор не создаёт дырок в интерфейсе. Пустой requirement не добавляет условия; непустой проверяет PAPI и при необходимости equals. Общие правила мира/состояния действуют дополнительно.

Конфиг является редактируемым источником шаблонов. `/le reload` валидирует его и синхронизирует зеркало каталога SQLite, а редактор записывает оба представления. Личный выбор и история остаются в SQLite. Устаревший редактор не может перезаписать более новую ревизию другого администратора.
