# Профиль игрока и приватность

[Главная](../README.md) · [Команды](COMMANDS.md) · [Плейсхолдеры](PLACEHOLDERS.md) · [Права](PERMISSIONS.md)

`/profile` открывает свой профиль, `/profile <ник>` или `/profile view <ник>` — профиль онлайн-игрока. Есть алиасы `/userinfo`, `/профиль`, `/я` и все варианты под `/le`. Явная форма `view` также позволяет открыть игрока, чьё имя совпадает с подкомандой. `/profile list` показывает доступные профили с текущими скинами.

## Главное меню

Компактная панель из 27 слотов повторяет структуру предоставленных примеров: голова выбранного игрока, пять разделов, нижние кнопки возврата/закрытия. Тексты находятся в `lang.yml → profile-menu`, данные и личный выбор — в SQLite. Карточки обновляются без повторного открытия меню.

- **Безопасность**: владелец открывает свой LoveAuth через `loveauth account`. Другим показывается только состояние авторизации; пароль, почта, сессии и чужие настройки не открываются.
- **Настройки**: владелец открывает личные параметры чата, сообщений, уведомлений, табло и отдельный раздел «Активность и приватность». В чужом профиле на этом месте находится доступ к разрешённой активности.
- **Персонализация**: свой ник, цвета/градиенты/сброс LoveEssential и каталог пометок LoveSubnames. В чужом профиле — только отображение ника и пометки.
- **Адаптации**: вместо раздела статистики показываются адаптация и прогресс LoveAdaptation. Подробный экран получает плейсхолдеры выбранного игрока для воды, Незера, пещер, высоты, бездны, боя и путешествий. Владелец может перейти в своё настоящее меню LoveAdaptation; просмотр чужого прогресса не меняет адаптации зрителя.
- **Репутация**: в чужом профиле сразу запускается `/rep <ник>` от LoveBehavior. Проверки времени игры, IP, задержки и права выполняет LoveBehavior. В своём профиле открывается `/behavior`, поскольку оценивать себя нельзя.

Кнопки сообщений и инвентаря в чужом профиле доступны по правам соответствующих модулей. Стандартная карточка убийств/смертей `cards.statistics` не выводится. Остальные карточки `profile.cards` используются в разделе активности; существующие числовые плейсхолдеры сохраняются для совместимости с TAB и интеграциями.

## Два независимых переключателя

`Профиль → Настройки → Активность и приватность` содержит два переключателя:

| Настройка | Команда | Результат |
| --- | --- | --- |
| Профиль для других | `/profile hide`, `/profile show`, `/profile toggle` | Закрывает/открывает весь профиль другим игрокам |
| То же, явный режим | `/profile privacy private`, `/profile privacy public` | Подходит для команд внешнего меню |
| Активность для других | `/profile activity hide`, `/profile activity show`, `/profile activity toggle` | Отдельно скрывает время игры, состояние и местоположение в интерфейсе профиля |
| Открыть настройки | `/profile settings` | Личные настройки |
| Открыть свою активность | `/profile activity` | Карточки активности и оба переключателя |

Владелец видит свой профиль и активность всегда. Обычный OP не обходит скрытие. При скрытии уже открытый чужой экран закрывается; доступ проверяется повторно при действии. Скрытые профили не попадают в список профилей и TAB-дополнение `/profile`. До загрузки настроек доступ для другого игрока закрыт. Переключение активности не скрывает адаптации, репутацию и пометки в открытом профиле.

Координаты другого игрока дополнительно требуют `loveessential.profile.location` и разрешённой владельцем активности. Приватность профиля относится к интерфейсу LoveEssential; самостоятельные команды и публичные API соседних плагинов регулируются их правилами.

## Команды и плейсхолдеры для внешних меню

Для кнопки открытия своего профиля в DeluxeMenus:

```yaml
left_click_commands:
  - '[player] loveessential:profile view %player_name%'
```

Или используйте готовую команду `%loveessential_profile_command%`: она возвращает `loveessential:profile view <настоящее-имя>` в контексте выбранного игрока. Строка не содержит начального `/`, чтобы её можно было использовать в `[player]`. Для другого игрока внешнее меню должно передать его имя или вычислить плейсхолдер в контексте этой цели.

| PlaceholderAPI | Значение |
| --- | --- |
| `%loveessential_profile_loaded%` | `true`, когда личные настройки загружены |
| `%loveessential_profile_visible%` | Профиль открыт для других: `true`/`false` |
| `%loveessential_profile_hidden%` | Профиль скрыт либо пока не загружен |
| `%loveessential_activity_enabled%` | Независимый выбор показа активности |
| `%loveessential_activity_visible%` | Активность доступна другим при открытом профиле |
| `%loveessential_profile_visibility_label%` | Локализованное состояние профиля |
| `%loveessential_activity_visibility_label%` | Локализованное состояние активности |
| `%loveessential_profile_command%` | Готовая команда открытия профиля цели |
| `%loveessential_profile_toggle_command%` | Команда переключения собственного профиля |
| `%loveessential_activity_toggle_command%` | Команда переключения собственной активности |

Флаги и готовые команды читаются из безопасного снимка без синхронного SQL. Глобальные плейсхолдеры здоровья/уровня/времени сохраняют прежний контракт; внешние панели учитывают флаги приватности перед показом своих данных. Произвольные PAPI-потребители не передают LoveEssential зрителя.

## Плейсхолдеры экосистемы

Шаблоны `profile-menu.*` используют реальные имена расширений:

| Плагин | Примеры |
| --- | --- |
| LoveAdaptation | `%loveadaptation_current_name%`, `%loveadaptation_current_progress%`, `%loveadaptation_water_progress%`, `%loveadaptation_water_status%` |
| LoveBehavior | `%lovebehavior_politeness_name%`, `%lovebehavior_playstyle_name%`, `%lovebehavior_politeness_points%` |
| LoveAuth | Авторизация через AuthOracle LoveCore; внешний PAPI `%loveauth_authenticated%` тоже поддерживается |
| LoveSubnames | `%lovesubnames_current%`, `%lovesubnames_unlocked_count%`, `%lovesubnames_total_count%` |

В `lang.yml` используйте `<papi:loveadaptation_current_name>`. Необязательный запасной текст: `<papi:loveadaptation_current_name:"—">`. Если PlaceholderAPI, расширение или значение недоступны, показывается запасной текст. В чужом профиле подставляются данные цели, а не зрителя.

Настройки воспроизводят нужные переходы из приложенных меню: грамматика идёт в LoveChatFilter, тихий режим/упоминания/канал — в Lovechat, приглашения — в LoveClans, обмен — в LoveTrades, табло — в LoveEssential. Канал переключается между локальным и глобальным. Каналы уведомлений используют типизированный LoveNotify из LoveCore и сохраняют правило хотя бы одного включённого канала. Недоступная интеграция отмечается в описании кнопки.

## Конфигурация и обновление

`modules/profile.yml`: `privacy` задаёт начальные значения, `links` — владельцев и команды интеграций, `setting-controls` — кнопки настроек, `adaptation-cards` — материалы и ключи строк. Существующие значения сохраняются при добавлении новых настроек. Личный выбор лежит в документе SQLite `profile-preferences` с ревизией; смена сессии и быстрое переподключение не подменяют сохранённое скрытие старым чтением.

Команды интеграций запускаются только от имени игрока после проверки владельца команды и прав. В них допускаются `{player}` (цель) и `{viewer}` (зритель). Консоль и OP из приложенных примеров не используются.

Если прежний DeluxeMenus регистрирует `/profile`, отключите его регистрацию либо используйте `/le profile` или `/loveessential:profile`. Приложенные YAML служили образцом структуры; LoveEssential не требует DeluxeMenus для этих экранов. Команды `workbench`/`enderchest` и алиасы `craft`/`ec` удалены; алиасы рецептов `crafts`/`recipe` сохранены.
