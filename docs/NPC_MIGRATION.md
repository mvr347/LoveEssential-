# NPC LoveEssential: редактор и переход с Citizens

## Новый редактор

`/npc` — список NPC, `/npc sel` — выбрать того, на кого смотрите,
`/npc edit` — редактировать выбранного. В верхней строке редактора раздел открывается
одним кликом: основное, внешность, взаимодействие, поведение, маршрут, диалоги,
расписание и физика. Отдельный экран выбора раздела больше не нужен.

В рабочей области под полями доступны предпросмотр, перенос точки к себе, переименование,
включение/выключение в черновике, сохранение черновика; публикация — в нижней панели.
Изменения включения, имени и позиции вступают в силу после публикации.
Предпросмотр использует существующий режим временного показа NPC.

Булевы настройки переключаются кликом. Небольшие списки (до 12 вариантов):
ЛКМ — следующий, ПКМ — предыдущий, Shift + клик — полный список с названиями.
Большие списки открывают выбор сразу. Числа поддерживают существующие изменения
ЛКМ/ПКМ и Shift; подробности показаны в подсказке поля.

Создать без заполнения GUI можно командами (потребуются права NPC-редактора):

```text
/npc create tavern_guard
/npc set name <gold>Страж трактира
/npc set type VILLAGER
/npc set movement stationary
/npc here
/npc publish
```

`create` открывает черновик и меню, но все поля можно заполнить командами.
`/npc save` сохраняет черновик без публикации; `/npc discard` отменяет его.
`/npc sel <номер>` выбирает существующего персонажа по номеру из `/npc`.
Для него работают `/npc edit`, `/npc skin`, `/npc path`, `/npc dialog`,
`/npc schedule` без повторного ввода номера.

## Если NPC уже созданы LoveEssential

Импорт и пересоздание не нужны. Обновите LoveEssential и перезапустите сервер:
новый редактор работает с теми же ID и базой. Обычная роль (банкир, торговец,
трактирщик) остаётся в плагине-владельце, а модель, расписание, движения и общие
диалоги находятся в LE. Участие в контракте задаётся привязкой к тому же ключу NPC.
Новые диалоги и рабочие смены нужно настроить; обновление не придумывает их за администратора.

## Перенос всех NPC Citizens

Сначала выполните перенос на копии сервера. Полный переход включает и импорт
моделей, и восстановление их ролей. Сам импорт не переносит любые Citizens traits.

1. В Citizens сохраните NPC через `/citizens save`. Остановите сервер и сделайте
   согласованную резервную копию `plugins/Citizens`, `plugins/LoveEssential` и
   папок всех плагинов, использующих NPC, включая их БД. Не копируйте только
   основной SQLite-файл у работающего сервера: данные могут находиться в WAL.
2. Установите совместимые актуальные сборки LoveCore, LoveEssential и плагинов
   с NPC. Оставьте `plugins/Citizens/saves.yml` на месте. Уберите JAR Citizens из
   папки загрузки (сохранив его в резервной копии), чтобы не показывать два набора NPC.
   Если другие плагины требуют Citizens, сначала решите их зависимости на копии сервера.
3. Запустите сервер в техническом режиме, без обычных игроков. Убедитесь, что LE
   загрузил SQLite и модуль `npc` включён, а миры с NPC доступны. В игре от администратора:

   ```text
   /npc import citizens all
   ```

   Для одного персонажа: `/npc import citizens 42`. Смотрите итоги: созданы,
   уже существуют, пропущены. Исправьте причины пропуска (например, незагруженный мир)
   и повторите импорт. NPC с тегом `citizens-id` повторно не создаются.
   Таблица `старый Citizens ID → новый ключ LE` записывается в
   `plugins/LoveEssential/citizens-import.yml`; это ключи привязок, а не обязательно
   публичные номера из `/npc`.
4. Переключите именно NPC-провайдер в `config.yml` каждого используемого плагина:

   ```yaml
   integrations:
     npc-provider: loveessential
   ```

   Добавьте поле в существующий раздел `integrations`, не создавайте второй одноимённый
   раздел. Это касается LoveShops, LoveBrewing, LoveContracts, LoveTweaks,
   LoveClans, LoveHunt, LoveClaims, LoveLeaderboards и других установленных
   плагинов с настройкой `integrations.npc-provider`. Названия папок Shop и Brew:
   **LoveShops** и **LoveBrewing**. Меняйте файлы на остановленном сервере после
   завершения импорта, затем запустите его снова.

   Общая команда переключения провайдера LoveCore меняет также интеграции скинов
   и revive. Для перехода только NPC достаточно настроек выше.
5. Проверьте привязки ролей по таблице ниже. После ручных изменений файлов
   перезапустите сервер, чтобы плагины прочитали новые ключи.

| Где хранится роль | Что происходит при переносе |
| --- | --- |
| LoveTweaks `herald.npc-key` | Импорт заменяет числовой Citizens ID новым ключом, если плагин включён |
| LoveClans `clans.guildmaster.npc-key`, `clans.banner.npc-key` | Аналогично |
| LoveHunt `npc.turn-in-key` | Аналогично |
| LoveContracts `npc.key` | Аналогично; это основной контрактник, не все участники сюжетов |
| LoveShops: банкир, торговцы и другие записи NPC | `/loveshopsadmin npc list`, затем `/loveshopsadmin npc rebind <номер записи> <новый ключ LE>`. Можно не писать ключ и смотреть на нового NPC. Сохраняйте существующую запись: её тип, настройки и связанные данные остаются |
| LoveBrewing: трактирщики | `/brewadmin npc list`, наведитесь на нового NPC и `/brewadmin npc bind <существующий ID трактирщика>`. Укажите старый ID, чтобы обновить его привязку, а не создать новую запись |
| Участники контрактных цепочек, другие конфиги и сторонние плагины | Вручную сопоставьте ссылки на NPC с таблицей импорта, включая `npc-key`, `target-npc-key` и определения именованных актёров. Ссылки `@actor:имя` сохраняют имя актёра; меняется его привязка к NPC |

Импорт переносит имя, тип сущности, позицию и поворот, скин, look-close и строки
голограммы. Маршруты, сторонние traits, команды, профессии и квестовые связи
вне перечисленных настроек автоматически не переносятся. Настройте их в новом
редакторе или плагине-владельце. NPC, которых не было в `Citizens/saves.yml`,
нужно создать в LE отдельно и привязать к прежним записям ролей.

## Проверка и откат

Проверьте `/npc`: количество, имена, миры, отсутствие дублей. У каждого типа NPC
проверьте привычную функцию; у банкира — внесение и возврат валюты при закрытии.
Для квестового NPC проверьте двух игроков с разным прогрессом: нужный диалог,
выполнение этапов, награду и возврат к обычной профессии. Отдельно проверьте
расписание, маршрут, репутационные реплики и повторный запуск сервера.

При неудаче остановите сервер и восстановите согласованный комплект JAR,
конфигов и БД из резервной копии, затем запустите прежний вариант. Не удаляйте
исходный `Citizens/saves.yml` и резервные копии до проверки всех ролей.
