# Кастомные крафты и первый вход

[Главная](../README.md) · [Команды](COMMANDS.md) · [Права](PERMISSIONS.md)

Нужны Java 25 и Paper/Purpur 26.2+. Редактору требуется `loveessential.content.edit` (входит в `loveessential.admin`). Главная панель `/le` содержит только настройки модулей; работа с содержимым открывается отдельными командами. Опубликованные определения хранятся в SQLite, названия и описания предметов — в локальных `messages` конфигов модулей и `gui.yml`. Несохранённый черновик редактора хранится до выхода или открытия другого черновика; кнопка «Сохранить» применяет его.

## Рецепты крафта

1. Откройте `/le recipes` (алиасы `/le recipe`, `/le crafts`, `/le рецепты`) и нажмите «Создать». ID назначится автоматически. Альтернатива — `/le recipes create`; для интеграций сохраняется необязательный явный ID: `/le recipes create sigil`.
2. Копируйте ингредиенты из руки/курсора в сетку 3×3. Одна заполненная ячейка означает один ингредиент. ПКМ очищает ячейку.
3. Скопируйте результат справа: сохраняется количество предметов, PDC, компоненты, модель, зачарования и другие метаданные.
4. Выберите крафт с формой или без неё; точное сравнение предметов либо только материала. По умолчанию используется точное сравнение. Задайте право и переключите активность, если нужно.
5. Сохраните. В каталоге `/le recipes` ЛКМ по рецепту открывает просмотр, ПКМ — редактор. Измените ингредиенты, результат, количество, режим или право и снова сохраните. Удаление доступно кнопкой в редакторе с подтверждением. Также работают `/le recipes open sigil`, `/le recipes edit sigil` и `/le recipes delete sigil`.

Это нативные `ShapedRecipe`/`ShapelessRecipe` Paper: расход ингредиентов, остатки и Shift-клик выполняет сервер. Ключ имеет вид `loveessential:craft_sigil`. Рецепты доступны в обычном верстаке и книге рецептов. Разрешения и LoveAuth проверяются при подготовке результата и крафте. Рецепты с совпадающими ингредиентами конкурируют по правилам Paper; используйте разные составы или метаданные.

При выключении `crafting` рецепты удаляются из реестра Paper; при включении восстанавливаются из загруженных документов SQLite. Уже открытое окно крафта не позволяет получить старый результат после изменения определения. Тексты точных ингредиентов участвуют в сравнении: после изменения перевода имени или lore предмета выполните `/le reload` для перерегистрации рецепта.

## Предметы при первом входе

`/le starter` и `/le starter edit` открывают редактор администратора с правом `loveessential.content.edit`. Игрок получает набор один раз автоматически при первом появлении после авторизации, без меню. Можно добавлять копии предметов, менять количества, удалять позиции, заменить набор копией 36 основных ячеек инвентаря или добавить настоящий свиток LoveTweaks. Сохраняется максимум 36 стеков; броня и вторая рука не копируются. Переключатель в редакторе приостанавливает выдачу набора.

При первом запуске, если документа набора ещё нет, LoveEssential один раз читает `first-join` из `plugins/LoveTweaks/config.yml`, включая enabled, количества, названия, lore и признак свитка. Тексты переводятся из `&`-цветов в MiniMessage в локальных `messages` конфигов модулей и `gui.yml`. Изменение старого конфига после импорта не меняет набор: дальше используйте редактор LoveEssential. Без секции LoveTweaks создаётся набор из железного меча и 16 единиц приготовленной говядины.

После успешной загрузки набора LoveEssential через публичный API Bukkit временно снимает только старый `FirstJoinItemsListener` LoveTweaks. Остальные слушатели и механики не затрагиваются; при отключении LoveEssential исходные регистрации восстанавливаются, если LoveTweaks продолжает работать. Обновление JAR LoveTweaks не требуется. Свиток создаётся его настоящей фабрикой `TeleportScroll.create()` с сохранением PDC/ItemsAdder. Без работающей фабрики набор ожидает восстановления; обычная бумага вместо свитка не выдаётся.

Право на набор определяется один раз при первом входе и записывается в SQLite. Сохранение playerdata во время регистрации LoveAuth не лишает игрока набора. Выдача ждёт авторизации. Если игрок вышел, ожидающий набор остаётся в SQLite и проверяется при следующем входе. Старые отметки `lovetweaks:first_join_received` учитываются; прежним игрокам новый набор автоматически не назначается.

Перед выдачей фиксируется состав ожидающей доставки. Весь набор должен помещаться в основной инвентарь: частичной выдачи и выпадения предметов на землю нет. Если места мало, игрок освобождает ячейки; автоматическая повторная проверка выдаёт ожидающий набор. Для восстановления между сохранением инвентаря и записью результата SQLite используется отметка в playerdata, сохраняемая вместе с инвентарём. Это дополнительная защита повторов, основной журнал остаётся в SQLite. Гарантии при повреждении файлов, ручном откате playerdata отдельно от базы или потере сохранения самим сервером не обеспечиваются: резервируйте базу, `lang.yml` и playerdata согласованно.

## Файлы и данные

- `modules/crafting/crafting.yml`: enabled, max-recipes.
- `modules/starter/starter.yml`: enabled.
- SQLite: документы `custom-craft`, `starter-kit`, `starter-delivery`, аудит изменений.
- `modules/crafting/gui.yml`: интерфейс `content.*`; созданные редактором тексты `content-text.*` находятся в конфиге crafting или starter по типу содержимого.

Сохранение проверяет ревизию документа: параллельный редактор не перезапишет чужое изменение. Ввод в чат показывает пояснение и кнопку отмены. Предметы интерфейса нельзя вынести Shift-кликом, цифрами, двойным нажатием или перетаскиванием.
