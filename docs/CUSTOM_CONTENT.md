# Свои меню, рецепты и первый вход

[Главная](../README.md) · [Команды](COMMANDS.md) · [Права](PERMISSIONS.md)

Нужны Java 25 и Paper/Purpur 26.2+. Редактору требуется `loveessential.content.edit` (входит в `loveessential.admin`). Главная панель `/le` содержит только настройки модулей; работа с содержимым открывается отдельными командами. Опубликованные определения хранятся в SQLite, собственные названия, описания и сообщения — в `lang.yml`. Несохранённый черновик редактора хранится до выхода или открытия другого черновика; кнопка «Сохранить» применяет его.

## Создание меню

1. `/le customgui create market` (коротко `/le gui create market`). ID: 1–48 строчных латинских букв, цифр, `_` или `-`.
2. Возьмите предмет в руку или на курсор, нажмите свободную ячейку. Редактор копирует предмет: оригинал остаётся вашим. Доступна 21 позиция содержимого стандартного меню на 54 ячейки.
3. В карточке кнопки задайте название, описание (строки через `|`), действия ЛКМ и ПКМ, условие. Нажатие на центральный предмет заменяет иконку копией предмета из руки/курсора.
4. Заголовок и право всего меню задаются в верхней панели. `-` снимает ограничение по праву. Предпросмотр показывает оформление без выполнения действий.
5. Сохраните. Игроки открывают `/le gui market` или выбирают меню через `/le gui`. Редактирование — `/le gui edit market`, удаление с подтверждением — `/le gui delete market`.

В списке ЛКМ открывает меню, ПКМ редактирует его при наличии права. В редакторе меню ПКМ удаляет кнопку. Название и описание кнопки поддерживают MiniMessage и шаблоны LoveEssential, например `<player>`, `<nickname>`, `<clan>`, `<health>`, `<papi:loveessential_playtime_hours>`. Значения подставляются при открытии меню; предметы рецепта и набора не персонализируются этими шаблонами.

Кнопка может последовательно выполнить до восьми действий отдельно для ЛКМ и ПКМ:

| Действие | Настройка |
| --- | --- |
| `menu` | ID другого своего меню |
| `message` | MiniMessage-сообщение; сохраняется в lang.yml |
| `command` | Команда от имени игрока, без `/`; корень должен быть в `actions.allowed-player-commands` файла `modules/npc.yml` |
| `charge` | Положительное количество физических монет EconomyService LoveCore |
| `sound` | Название Bukkit Sound |
| `starter` | Попытка получить ожидающий стартовый набор |
| `recipes` | Каталог рецептов |

Порядок виден в карточке последовательности. Первое неуспешное действие останавливает остальные. Уже выполненные действия не откатываются автоматически: например, не создавайте несколько последовательных списаний для одной покупки. Команды выполняются с обычными правами игрока. Меню не даёт OP и не исполняет команды от консоли.

Условия кнопки: доступ всем, право, минимальный баланс. Недоступный провайдер экономики скрывает кнопку. Условия, авторизация, включённость модуля и актуальная версия меню проверяются повторно при нажатии. Действие `menu` доступно также в NPC/диалогах через ActionEngine: `{"type":"menu","args":{"id":"market"}}`.

## Рецепты крафта

1. `/le recipes create sigil`.
2. Копируйте ингредиенты из руки/курсора в сетку 3×3. Одна заполненная ячейка означает один ингредиент. ПКМ очищает ячейку.
3. Скопируйте результат справа: сохраняется количество предметов, PDC, компоненты, модель, зачарования и другие метаданные.
4. Выберите крафт с формой или без неё; точное сравнение предметов либо только материала. По умолчанию используется точное сравнение. Задайте право и переключите активность, если нужно.
5. Сохраните. `/le recipes` — каталог, `/le recipes open sigil` — просмотр, `/le recipes edit sigil` — редактор, `/le recipes delete sigil` — удаление с подтверждением.

Это нативные `ShapedRecipe`/`ShapelessRecipe` Paper: расход ингредиентов, остатки и Shift-клик выполняет сервер. Ключ имеет вид `loveessential:craft_sigil`. Рецепты доступны в обычном верстаке и книге рецептов. Разрешения и LoveAuth проверяются при подготовке результата и крафте. Рецепты с совпадающими ингредиентами конкурируют по правилам Paper; используйте разные составы или метаданные.

При выключении `crafting` рецепты удаляются из реестра Paper; при включении восстанавливаются из загруженных документов SQLite. Уже открытое окно крафта не позволяет получить старый результат после изменения определения. Тексты точных ингредиентов участвуют в сравнении: после изменения перевода имени или lore предмета выполните `/le reload` для перерегистрации рецепта.

## Предметы при первом входе

`/le starter` показывает состав, `/le starter edit` открывает редактор, `/le starter claim` повторяет получение ожидающего набора. Можно добавлять копии предметов, менять количества, удалять позиции, заменить набор копией 36 основных ячеек инвентаря или добавить настоящий свиток LoveTweaks. Сохраняется максимум 36 стеков; броня и вторая рука не копируются. Переключатель в редакторе приостанавливает выдачу набора.

При первом запуске, если документа набора ещё нет, LoveEssential один раз читает `first-join` из `plugins/LoveTweaks/config.yml`, включая enabled, количества, названия, lore и признак свитка. Тексты переводятся из `&`-цветов в MiniMessage в `lang.yml`. Изменение старого конфига после импорта не меняет набор: дальше используйте редактор LoveEssential. Без секции LoveTweaks создаётся набор из железного меча и 16 единиц приготовленной говядины.

После успешной загрузки набора LoveEssential через публичный API Bukkit временно снимает только старый `FirstJoinItemsListener` LoveTweaks. Остальные слушатели и механики не затрагиваются; при отключении LoveEssential исходные регистрации восстанавливаются, если LoveTweaks продолжает работать. Обновление JAR LoveTweaks не требуется. Свиток создаётся его настоящей фабрикой `TeleportScroll.create()` с сохранением PDC/ItemsAdder. Без работающей фабрики набор ожидает восстановления; обычная бумага вместо свитка не выдаётся.

Право на набор определяется один раз при первом входе и записывается в SQLite. Сохранение playerdata во время регистрации LoveAuth не лишает игрока набора. Выдача ждёт авторизации. Если игрок вышел, ожидающий набор остаётся в SQLite и проверяется при следующем входе. Старые отметки `lovetweaks:first_join_received` учитываются; прежним игрокам новый набор автоматически не назначается.

Перед выдачей фиксируется состав ожидающей доставки. Весь набор должен помещаться в основной инвентарь: частичной выдачи и выпадения предметов на землю нет. Если места мало, игрок освобождает ячейки и нажимает «Забрать»; есть автоматическая повторная проверка. Для восстановления между сохранением инвентаря и записью результата SQLite используется отметка в playerdata, сохраняемая вместе с инвентарём. Это дополнительная защита повторов, основной журнал остаётся в SQLite. Гарантии при повреждении файлов, ручном откате playerdata отдельно от базы или потере сохранения самим сервером не обеспечиваются: резервируйте базу, `lang.yml` и playerdata согласованно.

## Файлы и данные

- `modules/customgui.yml`: enabled, max-menus.
- `modules/crafting.yml`: enabled, max-recipes.
- `modules/starter.yml`: enabled.
- SQLite: документы `custom-menu`, `custom-craft`, `starter-kit`, `starter-delivery`, аудит изменений.
- `lang.yml`: интерфейс `content.*`, созданные редактором тексты `content-text.*`.

Сохранение проверяет ревизию документа: параллельный редактор не перезапишет чужое изменение. Ввод в чат показывает пояснение и кнопку отмены. Предметы интерфейса нельзя вынести Shift-кликом, цифрами, двойным нажатием или перетаскиванием.
