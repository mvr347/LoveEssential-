# Миры, сценарии, диалоги и scoreboard

[Главная](../README.md) · [Команды](COMMANDS.md) · [Права](PERMISSIONS.md)

Требования: Paper/Purpur 26.2+, Java 25 и LoveCore. Конфигурация модулей — `modules/<имя>/<имя>.yml` для worlds, scenarios, dialogs и scoreboard. Определения и состояния хранятся в SQLite; собственные тексты — в локальных секциях `texts` конфигов модулей и `gui.yml`. Главное `/le` управляет только модулями. `/le guide` отложен и не регистрируется.

## Управление мирами

`/le worlds` (алиасы `/le world`, `/le mw`, `/le миры`) открывает нативный диалог. Для администрирования нужно `loveessential.worlds.admin`; переходы требуют `loveessential.worlds.teleport` и права конкретного мира, если оно задано.

| Команда | Действие |
| --- | --- |
| `/le worlds create` | Окно создания: имя, измерение, тип генерации, числовой сид |
| `/le worlds create NAME [NORMAL/NETHER/THE_END] [NORMAL/FLAT/AMPLIFIED/LARGE_BIOMES] [SEED]` | Создать и загрузить мир |
| `/le worlds import` | Окно импорта существующей папки мира |
| `/le worlds import NAME [ENVIRONMENT] [TYPE] [SEED]` | Импортировать существующую папку с `level.dat` |
| `/le worlds edit NAME` | Изменить параметры мира |
| `/le worlds info NAME` | Открыть ту же карточку настроек |
| `/le worlds load NAME` | Загрузить зарегистрированный мир |
| `/le worlds unload NAME` | Подтвердить сохранение и выгрузку пустого мира |
| `/le worlds tp NAME` | Перейти на точку появления |
| `/le worlds setspawn` | Сохранить текущую позицию как точку появления текущего мира |

В настройках доступны автозагрузка, право входа, PvP, сложность, принудительный режим игры, время, остановка дневного цикла, погода, размер и центр границы, правила мира и имя мира возрождения. Правила выбираются из списка; значение — `true`/`false` или целое число по типу правила. Пустое имя мира возрождения оставляет обычное поведение Minecraft.

Имя мира ограничено 1–48 латинскими буквами, цифрами, `_` и `-`. Импорт работает внутри папки миров сервера; внешние пути и символьные ссылки наружу отклоняются. Создание/загрузка выполняются через WorldCreator на серверном потоке и могут занять время. SQLite и проверка файлов выполняются асинхронно.

Перед выгрузкой требуется освободить мир от игроков; основной мир не выгружается. Папки миров не удаляются. Переходы учитывают авторизацию, бой, безопасную позицию и территориальный доступ LoveCore; вход в зарегистрированный мир с ограничением по праву проверяется и для телепортов других плагинов.

Доступен основной набор управления мирами. Раздельные инвентари, группы миров, клонирование/регенерация и связи ванильных Nether/End-порталов в эту реализацию не входят. Одному миру следует назначать одного владельца настроек: одновременное применение настроек другого менеджера миров может их изменять.

## Сценарии событий

`/le scenario` открывает список. Нужны `loveessential.scenarios.admin` и включённый модуль. Через диалоги создаются сценарии, выбираются событие, признак «один раз», мир, право доступа и последовательность шагов. Новый сценарий выключен до настройки.

Лимит запусков на игрока за минуту задаётся в `scenarios.max-starts-per-minute`; он ограничивает случайные циклы событий.

Команды: `list`, `create ID`, `edit ID`, `run ID`, `reset ID`, `delete ID`. `run` запускает сценарий для администратора, учитывая его обычные условия и журнал. `reset` с подтверждением сбрасывает только собственный журнал: реальные награды и списания при новом запуске могут повториться. Удаление сценария сохраняет журнал для аудита.

| Событие | Когда назначается сценарий |
| --- | --- |
| `FIRST_JOIN` | Первый вход игрока; право фиксируется до ожидания LoveAuth |
| `JOIN` | Каждый вход |
| `AUTH` | Событие успешной авторизации LoveCore |
| `WORLD_ENTER` | Переход между мирами |
| `RESPAWN` | После возрождения |
| `MANUAL` | Ручной запуск администратором |

Каждый шаг задаёт задержку (20 тиков = 1 секунда, максимум 72000) и действие: сообщение MiniMessage, actionbar, звук, разрешённая команда от игрока, открытие диалога, переход в мир, получение стартового набора, каталог рецептов, списание или выдача физических монет LoveCore. Команды исполняются с правами игрока и ограничены `actions.allowed-player-commands` из `modules/npc/npc.yml`. Произвольного Java/JavaScript, команд консоли и выдачи OP нет.

Шаги исполняются последовательно; неуспешное действие останавливает цепочку и помечает журнал `FAILED`. Отсутствие авторизации или невыполненное условие самого сценария приостанавливают его. Выход отменяет таймеры; `PENDING`-запуски читаются при следующем входе. Изменение определения останавливает старый запуск как `STALE`, чтобы уже запланированное действие не использовало изменённые настройки.

Курсор сохраняется **перед** действием. Поэтому после сбоя уже зарезервированный шаг не выполняется повторно, но сбой между записью курсора и действием может его пропустить. Это не транзакция между SQLite, миром Minecraft и сторонней экономикой. Для ценных предметных наград используйте существующую доставку starter либо специализированный сервис наград с собственным журналом.

Пример приветствия:

1. `/le dialog create welcome` — задать текст и ответы окна.
2. `/le scenario create first_visit` — событие `FIRST_JOIN`, «один раз» включено.
3. Добавить сообщение, затем `dialog` с параметром `welcome`, затем при необходимости `world` с именем мира и задержкой.
4. Включить сценарий после настройки. Важно: открытие окна не приостанавливает следующие шаги до ответа; действия после выбора ответа задаются в самом окне.

## Нативные диалоговые окна

`/le dialog` (алиас `/le dialogs`) открывает список. Для редактирования нужно `loveessential.dialogs.admin`. Доступны `create ID`, `edit ID`, `open ID`, `delete ID` с подтверждением.

Окно содержит заголовок, текст, необязательное право доступа, текстовые поля и до 12 ответов. Полям задаются ID, подпись, начальное значение и лимит длины. В параметре действия ответа доступно `${ID_поля}`. В заголовке, тексте и подписях ответов работают MiniMessage и плейсхолдеры LoveEssential/PAPI.

Ответ может закрывать окно, показывать сообщение, выполнять разрешённую команду игрока, открывать другой диалог, переходить в мир, проигрывать звук, открывать рецепты или запрашивать стартовый набор. У ответа может быть отдельное право. При ответе проверяются игрок, одноразовый токен, срок 3 минуты, доступ и ревизия окна. Ответ из старого или чужого окна не выполняется. Команды и поля не обходят разрешения назначенного действия.

Диалоги NPC тоже показываются нативными окнами; сохраняются проверки расстояния, видимости, условий и действий существующей системы NPC. Собственные окна могут открываться из NPC/сценариев действием `{"type":"dialog","args":{"id":"welcome"}}`. Для перехода в мир есть `{"type":"world","args":{"id":"island"}}`.

## MOTD

`/le motd` открывает окно редактирования двух строк описания в списке серверов. Требуется `loveessential.admin`. Есть предпросмотр и сохранение; возврат из предпросмотра сохраняет введённый черновик. Первый запуск переносит прежний `motd.text` в новый документ с отдельными ключами строк.

После сохранения новый MOTD применяется к запросам списка серверов. Выключение модуля `motd` оставляет стандартное поведение сервера. Тексты находятся по ключам документа `motd` в `modules/motd/motd.yml → texts`; `/le reload` перечитывает их. Одновременное сохранение устаревшего редактора отклоняется по ревизии.

## Перенос scoreboard LoveTweaks

`/le scoreboard` (также `/табло`) открывает личные восемь слотов без отдельного права. ЛКМ убирает и уплотняет строки, ПКМ заменяет, Shift+ЛКМ поднимает, Shift+ПКМ опускает. Выбор открывает каталог с фильтрацией и сортировкой. [Подробная схема](SCOREBOARD.md).

`/le scoreboard settings` (также `edit`) или кнопка администратора открывает отдельное меню управления с редактором заголовка, разделителя, нижней строки, максимума строк, отключённых миров и каталога строк. Можно добавлять, редактировать и удалять строки, задавать несколько шаблонов, категорию и PAPI-требование. Нужен `loveessential.admin`. Шаблоны находятся в `modules/scoreboard/scoreboard.yml → catalog`, определения зеркалируются в SQLite.

При первом запуске один раз импортируются:

- `scoreboard` из конфига LoveTweaks: оформление, категории, шаблоны вариантов, требования и готовые наборы;
- `scoreboard_players` и `scoreboard_placeholders` из `lovetweaks.db` (либо старый `scoreboard_data.yml`/`.bak`): включённость, вид списка, порядок и номера вариантов игроков.

Исходные файлы не изменяются, новые данные LoveEssential не перезаписываются повторным запуском импорта. Дальше настройка выполняется в LoveEssential. На экране сохраняется раскладка парами с разделителями и максимумом 15 физических строк. Недоступные PAPI-строки скрываются до восстановления провайдера, выбор игрока не удаляется.

Адаптер для текущего LoveTweaks останавливает только `scoreboardTask`, снимает только ScoreboardListener и передаёт команду. Остальные задачи LoveTweaks продолжают работать; при отключении LoveEssential старый обработчик и периодическое обновление восстанавливаются. Для старой версии без публичного отключения используется проверенный адаптер известного поля задачи. Если контракт версии не совпал, новое табло приостанавливается с предупреждением вместо одновременного управления.

С нативным TAB LoveEssential sidebar использует его scoreboard, сохраняя команды имён и остальные objectives. При чужом scoreboard не перезаписывает его. Для внешнего TAB sidebar обычно следует настраивать в самом TAB: личное табло LoveEssential не захватывает чужую доску. При включённом модуле scoreboard прежняя статическая `tab.sidebar` уступает ему.

## Проверка и резервные копии

Сохраняйте `loveessential.db`, `lang.yml`, конфиги модулей и папки миров согласованно. `/le backup` копирует только SQLite. Диалоговые формы и сценарии проверяются автоматическими тестами; визуальный прогон нативных окон, настоящая генерация/выгрузка миров и совместная работа с установленным LoveTweaks требуют проверки на тестовом Paper/Purpur перед рабочим сервером.

Расширенные правила миров, режимов, доступа и API временной замены табло описаны в [руководстве scoreboard](SCOREBOARD.md).
