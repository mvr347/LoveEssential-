# Руководство администратора

[Главная](../README.md) · [Команды](COMMANDS.md) · [Плейсхолдеры](PLACEHOLDERS.md) · [Права](PERMISSIONS.md)

Модульный плагин для **Paper / Purpur 26.2+ и Java 25**. NPC, редакторы, маршруты и диалоги, оформление списка игроков, общая SQLite-база и интеграции с существующим LoveCore.

## Сборка и установка

```bash
./mvnw verify
```

Готовый плагин: `plugin/target/LoveEssential-2.0.0-SNAPSHOT.jar`. API для разработчиков: `api/target/loveessential-api-2.0.0-SNAPSHOT.jar`.

1. Установить Java 25 и Paper/Purpur 26.2. Сборка проверяется против Paper API `26.2.build.100-stable`; новые версии требуют проверки перед обновлением рабочего сервера.
2. Установить современный LoveCore. API закреплён на commit [`5a99cdb141`](https://github.com/mvr347/LoveCore/tree/5a99cdb1413be77d4b7a2dcbfedcc06f62d1c7ba). Старые сборки ядра с другим экономическим API не подходят.
3. Поместить JAR LoveEssential в `plugins/` и запустить сервер.
4. Открыть `/le` в игре. Общие параметры находятся в `plugins/LoveEssential/config.yml`, настройки каждого модуля — в `plugins/LoveEssential/modules/<модуль>.yml`, все собственные тексты — в `lang.yml`.

NPC используют нативные сущности Paper, включая **MANNEQUIN** со скином игрока. Citizens, ProtocolLib и PacketEvents для этого backend не требуются. Манекен — отдельная сущность Minecraft; он не добавляется фиктивным игроком в tablist.

## Панель управления и перенос настроек

`/le` открывает административную панель только с настройками и переключателями модулей, `/le help` — отдельный каталог всех команд. `/le npc` показывает NPC с кнопками создания, редактирования и удаления. Удаление требует отдельного подтверждения с ID объекта; команда эквивалентна `/le npc delete <id> confirm`. `/le skin` открывает выбор скина по имени и возврат собственного скина.

`/le module` показывает модули. ЛКМ открывает настройки, ПКМ включает или отключает модуль. `/le module <имя>` и `/le tab` открывают дерево параметров: разделы, переключатели, строки, числа и списки. Настройки сохраняются атомарно в файл своего модуля и применяются после проверки. Предыдущее состояние файла сохраняется в `.bak`; конфликт одновременного редактирования отклоняется. Вложенные объекты внутри списков редактируются непосредственно в YAML.

`/le homes`, `/le portal` и `/le hologram` открывают меню объектов. Для портала сначала выберите первую точку, затем перейдите ко второй и создайте область, после этого задайте назначение. Голограммы можно создавать, дополнять строками, перемещать и удалять через меню.

Стандартные меню используют 54 слота: верхние два ряда, один нижний ряд, свободные боковые стенки, до 21 элемента на странице и пагинация 36/44. Названия и описания без курсива; перед действиями есть разделитель, недоступные элементы объясняют причину. Новые тексты добавляются в существующий `lang.yml` без замены пользовательских переводов.

При первом запуске этой версии старые разделы `npc`, `tab`, `home`, `afk`, `night-skip`, `actions` и флаги `modules` автоматически переносятся из основного конфига в `modules/`. `actions` располагается в `modules/npc.yml`. Исходник сохраняется как `config.yml.pre-modules.bak`. Если файл модуля уже существует, его явно заданные значения имеют приоритет. Ошибка YAML отменяет загрузку; текущая рабочая конфигурация остаётся активной. В основной конфиг настройки модулей больше не записываются.

Для MANNEQUIN и ARMOR_STAND исправлена настройка экипировки: шанс выпадения задаётся только Mob, как требует Paper. Выпадение вещей и опыта NPC блокируется обработчиком смерти. При остальных ошибках создания журнал содержит ID, тип сущности и полный стек исключения.

## Создать NPC в игре

Администратору с `loveessential.admin`:

```text
/npc wizard
```

Семь экранов: идентификатор и параметры → внешность и экипировка → доступ и взаимодействие → поведение → маршрут → диалоги → расписание и физика. В мастере доступны скин, размер, поза, возраст, шесть слотов экипировки, тип клика, требование прямой видимости, задержка и звук взаимодействия, коллизия, гравитация, неуязвимость, двери и ограничения маршрута. Стандартные условия и действия выбираются в меню, затем мастер запрашивает параметры. Текст вводится в чат и перехватывается мастером; альтернативный ввод — `/le input значение`.

```text
/npc create gate_guard
/npc set name <gold>Страж ворот
/npc set type MANNEQUIN
/npc set skin Notch
/npc set main-hand IRON_SWORD
/npc here
/npc save
/npc publish
```

`save` сохраняет черновик, `publish` проверяет и публикует NPC. Черновик восстанавливается после выхода/перезапуска. При редактировании существующего NPC его ID остаётся неизменным. Перед открытием другого черновика текущий следует отменить через `/npc discard`.

```text
/npc edit gate_guard
/npc clone gate_guard market_guard
/npc preview
/npc list
/npc select
/npc debug gate_guard
/npc delete gate_guard confirm
```

Клонирование открывает новый черновик с отдельными ключами локализации. Импорт/экспорт: `/npc export gate_guard`, затем `/npc import gate_guard new_guard`. Файлы находятся в `plugins/LoveEssential/exports/`; импорт открывает черновик, который нужно проверить и опубликовать.

### Маршруты

В активном черновике:

```text
/npc path add
/npc path mode PING_PONG
/npc path point 1 wait 60
/npc path point 1 speed 1.2
/npc path point 1 radius 0.6
/npc path remove 2
/npc path move 3 1
/npc path undo
/npc path redo
/npc path record
/npc path tool
/npc path show
/npc path test
/npc path pause
/npc path resume
/npc path step
```

`record` переключает запись перемещения с расстоянием между точками не менее четырёх блоков. Инструмент добавляет текущую позицию по клику. Подсветка и тестовый экземпляр видны только редактору; действия точек в предпросмотре не выполняются.

Режимы: `ONCE`, `LOOP`, `PING_PONG`, `RANDOM`; поведение `movement`: `route`, `follow`, `stationary`. Следование настраивается через `follow-player` и `follow-distance`. Без имени NPC выбирает ближайшего подходящего игрока. При потере цели останавливается.

Путь ищется ограниченным A* по неизменяемому снимку загруженной области. Переходы через другие миры, полёт, разрушение блоков и принудительная загрузка чанков в этот наземный backend не входят. Длинные маршруты разбиваются на близкие точки. Двери открываются только при `can-open-doors: true`; вода допускается при `avoid-water: false`. Движение применяет небольшие перемещения на серверном потоке.

### Диалоги

```text
/npc dialog node hello <yellow>Чем могу помочь?
/npc dialog node job <gray>Зайди на доску контрактов.
/npc dialog answer hello work job Ищу работу.
/npc dialog answer hello leave end До встречи.
/npc dialog start hello
/npc publish
```

Графы проверяются на отсутствующие переходы и недостижимые узлы. Циклы разрешены, число переходов сессии ограничено. Ответ содержит nonce, узел и ID; сервер повторно проверяет ревизию, доступ и расстояние. Кнопки устаревшего диалога не исполняются.

Расширенные команды принимают JSON. Например:

```text
/npc set access {"type":"reputation","args":{"min":"30"},"children":[]}
/npc set actions [{"type":"lovecontracts:board","args":{}}]
/npc dialog answer-condition hello work {"type":"authenticated","args":{},"children":[]}
```

Команды `answer-actions` и `path point N actions` принимают массив действий. `path point N condition` принимает дерево условия.

### Настройки NPC

Настройки задаются через `/le npc set параметр значение` или мастер. Переключатели изменяются кликом; типы сущностей, экипировка, позы, режимы движения и звуки выбираются в меню с пагинацией. Имена и числовые значения вводятся в чат или `/le input`; `cancel` возвращает в меню.

| Параметры | Назначение |
|---|---|
| `skin`, `pose`, `scale`, `baby` | Облик, поза, размер, возраст |
| `main-hand`, `off-hand`, `helmet`, `chestplate`, `leggings`, `boots` | Экипировка, материал Bukkit |
| `description-key`, `name-visible`, `glowing`, `silent` | Описание, имя и эффекты |
| `personal`, `visibility`, `access`, `require-auth` | Персональные экземпляры и условия |
| `activation-range`, `interaction-range`, `cooldown-ms` | Дистанции и задержка кликов |
| `look-at`, `look-range`, `pause-on-interact` | Реакция на игрока |
| `movement`, `speed`, `follow-player`, `follow-distance` | Движение |
| `avoid-water`, `can-open-doors` | Навигация |
| `stuck-ticks`, `stuck-policy`, `teleport-on-stuck` | Застревание |
| `enabled-hours`, `hour-from`, `hour-to` | Расписание по игровому времени, 0–23999 |
| `collidable`, `gravity`, `invulnerable`, `enabled` | Физика и включение |

`stuck-policy`: `PAUSE`, `SKIP`, `RETURN_HOME`. Телепорт при возврате включается отдельно через `teleport-on-stuck`; его место проверяется на безопасность и территорию. Скин применяется к MANNEQUIN; особенности других сущностей зависят от их типа.

## Tablist и nametag

Два режима выбираются через `engine` в `modules/tab.yml` или в меню `/le tab`.

| Функция | `native` | `tab` |
|---|---|---|
| Header/footer, контекстные профили | Да | Да |
| Группы, prefix/suffix, сортировка | Да | Да |
| Nametag, коллизия, видимость | Да | Да |
| Анимации, плейсхолдеры Love/PAPI | Да | Да |
| Playerlist/below-name objective | Да | Да |
| Sidebar и несколько bossbar | Да | Да |
| Layout с фиктивными слотами | — | TAB |
| Полная схема условий/групп/пользователей TAB | — | TAB |
| Сетевой/global tablist | — | TAB с его proxy-настройкой |

Режим `native` работает средствами Paper. Учитывает видимость игрока для зрителя, сохраняет предыдущий scoreboard и по умолчанию уважает scoreboard другого плагина.

Для функциональности уровня NEZNAMY TAB установите **TAB и PlaceholderAPI**, затем:

1. Выберите `engine: tab` в `modules/tab.yml`.
2. Настройте `external.config`, `external.groups`, `external.animations` в `modules/tab.yml` либо через `/le tab`. Ссылки `*-key` ведут в `lang.yml`; ПКМ по такому параметру открывает редактирование текста.
3. Выполните `/le tab export`, затем `/le reload`.

Раздел `external` файла `modules/tab.yml` передаёт полную схему настроек установленного TAB: можно добавлять его штатные параметры. Экспорт выполняется только командой администратора, создаёт резервные копии `*.loveessential.bak` и вызывает `tab reload`. LoveEssential в этом режиме не создаёт конкурирующие teams/objectives.

`@lang(tab.header)` преобразуется в `%loveessential_text_tab.header%`. Тексты остаются в `lang.yml`. Переключатели запоминания выбора в поставляемой конфигурации TAB отключены; настройки игроков LoveEssential сохраняет в SQLite.

### Плейсхолдеры в lang.yml

MiniMessage-теги: `<player>`, `<viewer>`, `<world>`, `<visible_online>`, `<max_players>`, `<clan>`, `<reputation>`, `<territory>`, `<ping>`, `<suffix>`, `<afk>`, `<animation:kingdom>`, `<papi:identifier>`.

PAPI: `%loveessential_afk%`, `%loveessential_vanished%`, `%loveessential_authenticated%`, `%loveessential_clan%`, `%loveessential_reputation%`, `%loveessential_text_КЛЮЧ%`.

Значения обычных переменных экранируются. При добавлении текстов мастером генерируются отдельные ключи; неудачная публикация не переписывает тексты активной ревизии.

## Хранение и потоки

`loveessential.db` содержит определения, маршруты, диалоги, черновики, профили, позиции, настройки модулей, историю изменений и журнал публикаций. Структуры NPC сериализованы в JSON внутри SQLite; рабочие `npcs.yml`, `paths.yml` и файлы данных игроков не создаются.

- HikariCP: небольшой пул SQLite, WAL, foreign keys, busy timeout.
- Один последовательный writer на virtual thread с ограниченной очередью.
- Ограниченные асинхронные чтения и I/O на virtual threads.
- ConcurrentHashMap: определения, реестры, сессии.
- Caffeine: профили и вычисления PlaceholderAPI с лимитами размера/времени.
- Отдельный ограниченный CPU-пул A*; Bukkit-мир доступен только на серверном потоке.
- Проверка ревизии в транзакции защищает от перезаписи чужих изменений, в том числе после удаления и повторного создания ID.

`lang.yml` содержит весь собственный отображаемый текст. `config.yml` хранит общие параметры хранилища; `modules/*.yml` — настройки модулей и ссылки на ключи локализации. Экспортные файлы предназначены для переноса, рабочим источником данных остаётся SQLite.

Публикация текста и определения использует журнал подготовки: после сбоя восстанавливаются ключи локализации. Неиспользуемые ключи допустимы. Физическая валюта и произвольные внешние действия не образуют транзакцию с SQLite: для составных торговых операций используйте сервис владельца домена, а не цепочку несвязанных действий.

## Интеграции Love

LoveCore подключён как `provided` API, его классы не копируются в JAR. Сервисы разрешаются при обращении, поэтому поздняя регистрация нового провайдера учитывается.

| Источник | Использование |
|---|---|
| AuthOracle / LoveAuth | Авторизация, запрет действий при недоступном поставщике |
| ReputationOracle / LoveBehavior | Условия и изменения репутации, оформление |
| ProfileOracle / LoveClans | Кланы и условия доступа |
| TerritoryOracle / LoveClaims | Создание, навигация, телепортация |
| CombatState | Запрет телепортации в бою |
| LoveEconomy | Физические монеты, `balance`, `charge`, `give`, банкир |
| LoveNotify | Интерактивные сообщения и диалоги |
| StatBus / LoveLeaderboards | Статистика взаимодействий, ответов и телепортов |
| LoveSubnames | Суффикс через PlaceholderAPI |
| LoveContracts | Действия `lovecontracts:board`, `lovecontracts:player-board`, `lovecontracts:my` |
| LoveShops | Действие `loveshops:banker` |
| LoveChat | Ввод мастера отменяет AsyncChatEvent на LOWEST; `/le input` служит альтернативой |

Адаптеры меню LoveContracts/LoveShops используют проверенные публичные методы соседей. При несовместимой версии они отказывают с диагностикой, без подавления ошибки. Собственные тексты соседних меню принадлежат локализации соответствующего плагина.

Другие Love-плагины и будущий LoveQuests подключаются через реестр условий, действий и приоритетных взаимодействий. Наличие `softdepend` само по себе не объявляется готовой предметной интеграцией. Квестовый провайдер регистрирует взаимодействие с приоритетом выше обычного меню; `true` означает, что он обработал клик.

```java
LoveEssentialService api = Bukkit.getServicesManager().load(LoveEssentialService.class);
var registration = api.registerCondition("lovequests:active", (player, args) -> {
    return quests.hasActive(player.getUniqueId(), args.get("id"))
        ? LoveEssentialService.Verdict.ALLOW
        : LoveEssentialService.Verdict.DENY;
});
var interaction = api.registerInteraction("lovequests:dialog", 1000, (player, npc) -> {
    return quests.openRelevantDialog(player, npc.id());
});
// При отключении соседнего плагина:
registration.close();
interaction.close();
```

Регистрация, сохранение NPC и игровые callback выполняются на серверном потоке. Методы работы с профилем возвращают CompletableFuture. Ключи профиля имеют namespace, например `lovequests.chapter`; произвольная Java-сериализация не применяется. Авторизация, кланы и экономика остаются у их владельцев, в PlayerProfile не создаётся второй источник истины.

## Дополнительные модули

Дома с лимитом, несколько спавнов, TPA/Back с безопасной телепортацией, постоянный vanish, AFK, смена скина по имени, сидение/посадка, ускорение ночи, MOTD, join/quit, простые TextDisplay-голограммы, прямоугольные порталы и частицы следов.

```text
/hologram create market <gold>Рынок
/hologram addline market <gray>Добро пожаловать!
/hologram move market
/portal pos1
/portal create gate
/portal destination gate
```

`pos1` запоминает первый угол, `create` — второй, `destination` — точку назначения. Эти вспомогательные реализации не объявляются полной заменой всех расширенных механик CMI из исходного ТЗ.

Все команды доступны и самостоятельно, и через `/le`: `/le skin`, `/le home`, `/le sethome`, `/le spawn`, `/le tpa`, `/le profile`, `/le portal` и остальные. Русские алиасы работают в обоих вариантах, например `/le домой`. При конфликте команды можно использовать `/loveessential:loveessential home`. TAB дополняет вложенные ветки, имена NPC, домов, спавнов, игроков, настройки, режимы и подтверждение удаления.

## Управление и проверка

```text
/le module npc disable
/le module npc enable
/le module tab info
/le reload
/le integrations
/le backup
```

Состояние модулей, заданное командой или меню, сохраняется в SQLite и имеет приоритет над `enabled` в соответствующем `modules/<модуль>.yml`. `/le reload` перечитывает общие параметры, все модули и язык; размер очереди SQLite и число потоков A* требуют перезапуска. Резервная копия SQLite создаётся через `VACUUM INTO`; отдельно сохраняйте `lang.yml`, `config.yml` и папку `modules/`.

CI собирает JAR на Java 25 и выполняет тесты SQLite, A*, графов, сортировки, экспорта TAB и жизненного цикла/команд через MockBukkit 26.2. Полёт клиента, визуальное поведение манекенов, Purpur и сетевой TAB требуют игрового прогона на целевой сборке сервера; результаты нагрузочного теста не заявляются.

## Личные сообщения, инвентарь и досье игроков

Новые функции доступны как отдельные команды и как подкоманды `/le`, с русскими алиасами и TAB. `/le` содержит кнопки профиля, личных сообщений и инвентаря.

| Команда | Действие |
| --- | --- |
| `/le msg` | Меню выбора получателя, головы с текущими скинами, настройки сообщений |
| `/le msg <игрок> <текст>` | Личное сообщение; алиасы `/tell`, `/w`, `/pm`, `/лс` |
| `/le reply <текст>` | Ответ последнему собеседнику; `/r`, `/ответ` |
| `/le ignore [игрок]` | Переключить игнор; без аргументов — GUI настроек и игнор-листа |
| `/le msgtoggle` | Включить или отключить личные сообщения |
| `/le invsee` | Выбор онлайн-игрока для просмотра инвентаря |
| `/le invsee <игрок> [view\|edit]` | Живой просмотр либо редактирование инвентаря |
| `/le profile [игрок]` | Досье себя или онлайн-игрока; алиас `/userinfo` |
| `/le profile list` | Каталог доступных игроков с их скинами |

Сообщения учитывают LoveAuth, видимость/vanish, AFK, настройки обоих собеседников, лимит длины и задержку отправки. Нажатие на входящее сообщение подставляет команду ответа конкретному отправителю. Текст игрока не интерпретируется как MiniMessage. Игнор-лист привязан к UUID и сохраняется в SQLite вместе с настройкой приёма сообщений. Удалить из игнор-листа можно и вышедшего игрока через GUI или по сохранённому имени. Содержимое переписки не записывается в базу. Синхронное отменяемое `PrivateMessageEvent` из API позволяет LoveChat/LoveChatFilter и другим плагинам проверять и заменять текст **до доставки**; отдельного провайдера фильтра в текущем LoveCore API нет, поэтому для подключения фильтра нужен обработчик этого события.

Инвентарь открывается в режиме просмотра. Для изменения нажмите переключатель режима или укажите `edit`. Ряды 1–3 показывают основное хранилище, ряд 4 — хотбар, первые пять слотов ряда 5 — ботинки, поножи, нагрудник, шлем и вторую руку. В режиме редактирования ЛКМ переносит/объединяет стеки, ПКМ забирает половину или кладёт один предмет. Обычные клики по своему нижнему инвентарю позволяют брать предметы для передачи. Shift, цифры, двойной клик, выбрасывание, creative-клонирование и перетаскивание заблокированы. Перед изменением слот сравнивается с настоящим инвентарём; при расхождении экран обновляется. При закрытии старый снимок не восстанавливается. Выход/смерть игрока, отключение модуля и потеря прав прекращают доступ. Работа с предметами выполняется на серверном потоке; ванильные инвентари сохраняет Minecraft.

| Право | По умолчанию |
| --- | --- |
| `loveessential.messages` | Все игроки |
| `loveessential.profile` | Все игроки |
| `loveessential.profile.location` | OP; владелец всегда видит свою карточку местоположения |
| `loveessential.invsee` | OP; только просмотр |
| `loveessential.invsee.edit` | OP; редактирование, дополнительно к просмотру |

`loveessential.admin` включает перечисленные права. Права проверяются повторно при действии, а не только при открытии меню.

Конфиги: `modules/messages.yml`, `modules/inventory.yml`, `modules/profile.yml`. Все тексты находятся в `lang.yml`. В `profile.yml` карточки имеют `enabled`, `material`, `title-key`, `lore-keys` и необязательное `permission`; отображаются первые 21 доступная карточка. Эти настройки доступны через `/le module profile`. Строки карточек поддерживают родные теги и `<papi:идентификатор>` сторонних плагинов. Голова берётся из текущего PlayerProfile, включая скин, установленный через `/le skin`. По умолчанию координаты, территория и технические статусы находятся в карточке с отдельным правом.

Досье показывает личность, здоровье, питание, опыт, игровое время, статистику, клан и репутацию LoveCore, монеты LoveEconomy и территорию LoveClaims. Недоступные интеграции дают пустое значение. Снимки информации (включая URL/модель скина) сохраняются асинхронно в SQLite в поле профиля `loveessential.player-info`, периодически и при выходе. GUI и инвентарь работают с онлайн-игроками. Плейсхолдеры числовых/текстовых полей читают неизменяемый снимок, обновляемый на серверном потоке, поэтому их можно запрашивать асинхронно; стандартный интервал — 40 тиков.

Поля доступны как `%loveessential_<поле>%` в PlaceholderAPI и `<поле>` в шаблонах LoveEssential:

- `player`, `uuid`, `display_name`, `world`, `x`, `y`, `z`, `ping`, `gamemode`, `gamemode_name`;
- `health`, `max_health`, `food`, `saturation`, `level`, `exp` (процент текущего уровня), `total_exp`;
- `playtime_seconds`, `playtime_hours`, `playtime_minutes` (остаток минут), `first_join`, `last_seen` (UTC);
- `kills`, `mob_kills`, `deaths`, `jumps`, `damage_dealt`, `damage_taken`, `walk_km`, `homes`;
- `clan`, `reputation`, `territory`, `balance`, `currency`, `skin_url`, `skin_model`;
- `afk`, `vanished`, `authenticated`, `combat`, `flying`, `flight_allowed` (`true`/`false` в PAPI); для каждого есть `<поле>_state` с переводом «Да/Нет»;
- родной `<afk>` сохраняет прежнюю роль декоративного статуса TAB; для значения в карточке используйте `<afk_state>`.

Например, `%loveessential_health%`, `%loveessential_playtime_hours%`, `%loveessential_skin_url%`, либо строка в `lang.yml`: `'<gray>Уровень: <white><level> <gray>Клан: <gold><clan>'`. Поля местоположения в PAPI предоставляются доверенным плагинам без проверки зрителя: размещайте их только в нужных административных шаблонах. Плейсхолдеры становятся доступны после первого обновления снимка; после выхода они возвращают пустое значение.

## Никнеймы, цвета и градиенты

`/le nick` открывает меню с текущим результатом, вводом имени, палитрой 16 цветов, HEX-цветом, готовыми/своими градиентами и сбросами. Алиасы: `/nick`, `/nickname`, `/ник`, `/никнейм`; все работают также через `/le`. Настройки находятся в `modules/nickname.yml`, переводы — в `lang.yml`, индивидуальный ник и цвета — в SQLite (документы `nickname`, UUID игрока, ревизия и аудит изменений).

| Команда | Результат |
| --- | --- |
| `/le nick set Аврора` или `/le nick Аврора` | Установить ник, сохранив текущие цвета |
| `/le nick color gold` | Один из стандартных цветов |
| `/le nick color #ff6699` | Произвольный HEX-цвет |
| `/le nick gradient #ff6699 #ffcc66 #55ffff` | Градиент из 2–5 цветов |
| `/le nick color reset` или `/le nick gradient reset` | Сбросить только оформление; ник сохраняется |
| `/le nick reset` | Вернуть настоящее имя аккаунта и стандартное оформление |
| `/le nick player Alice set Аврора` | Изменить ник онлайн-игрока при наличии права `loveessential.nick.others`; также доступны `color`, `gradient`, `reset` |

В меню полный сброс требует подтверждения. `default-color` задаёт оформление после сброса; пустая строка означает отсутствие заданного цвета, поэтому цвет может наследоваться из шаблона чата/TAB. Имена допускают буквы Unicode, цифры и `_`; длина по умолчанию 3–24 символа. Теги MiniMessage, пробелы, коды форматирования и управляющие символы в имени не принимаются. Защита `prevent-impersonation` запрещает точное совпадение без учёта регистра с именем другого онлайн-игрока, известного серверу аккаунта или ником другого онлайн-игрока; параллельные сохранения резервируют имя на время записи. Это не глобальный реестр уникальных офлайн-псевдонимов.

Права `loveessential.nick`, `loveessential.nick.color`, `loveessential.nick.gradient` по умолчанию доступны игрокам; `loveessential.nick.others` — OP. Все входят в `loveessential.admin`. Сброс оформления доступен обладателю `loveessential.nick`, в том числе после снятия права на цвет/градиент.

| PlaceholderAPI | Значение |
| --- | --- |
| `%loveessential_nickname%` | Цветной ник с точными RGB-цветами в формате `§x…` |
| `%loveessential_nickname_plain%` | Ник без форматирования; после сброса — имя аккаунта |
| `%loveessential_nickname_mini%` | Ник, сериализованный в MiniMessage |
| `%loveessential_real_name%` | Настоящее имя аккаунта |
| `%loveessential_nickname_active%` | Есть ли индивидуальное имя или оформление (`true`/`false`) |
| `%loveessential_nickname_style%` | `default`, `color` или `gradient` |
| `%loveessential_nickname_colors%` | Выбранные HEX-цвета через запятую; пусто при стандартном оформлении |

В `lang.yml` используйте компонентный `<nickname>`, обычные `<nickname_plain>` и `<real_name>`. Пример: `'<nickname> <dark_gray>(<real_name>)'`. `<player>` продолжает обозначать настоящее имя; только шаблон имени в TAB подставляет ник автоматически при `apply-to-tab: true`. Встроенный TAB сохраняет групповые префиксы и суффиксы, включая LoveSubnames. Для внешнего TAB работают `%loveessential_nickname%` и стандартные экспортированные `@lang(tab.name)` / `@lang(tab.groups.<группа>.name)`; собственные шаблоны можно явно перевести на `<nickname>`.

`apply-display-name` управляет Bukkit displayName: чат, использующий это имя, увидит оформление. Для LoveChat или другого форматтера со своим шаблоном подставьте `%loveessential_nickname%` (либо MiniMessage-вариант, если форматтер ожидает его). `apply-to-messages` управляет именами в личных сообщениях. Ответы, команды, UUID, права и скин остаются привязаны к настоящему аккаунту. При отключении модуля активное отображение возвращается к стандартному, сохранённый ник можно восстановить включением модуля.

NPC универсальны: категории и ролевые шаблоны удалены. Назначайте действия, диалоги, движение и внешний вид независимо. Для списка точек откройте страницу маршрута и нажмите «Редактировать точку». В меню действий кнопка сверху показывает назначенные действия: ЛКМ перемещает действие раньше, ПКМ открывает подтверждение удаления.

Запросы в чат показывают контекст, объяснение, пример и текущее значение, если оно есть. Нажмите «ОТМЕНИТЬ ВВОД» для возврата. После ошибки исправьте значение в том же запросе; отмена старого запроса не закрывает новый.
