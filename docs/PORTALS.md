# Порталы

[Главная](../README.md) · [Ограничения модулей](MODULE_ACCESS_AND_GUI.md)

`/портал мастер` или `/le portal wizard` открывает мастер с автоматически назначенным ID. Настройка доступна с `loveessential.admin`; базовый вход в портал не требует этого права. Список — `/портал`, изменение — `/портал изменить ID`, удаление с подтверждением — `/портал удалить ID`.

1. Выберите первый и второй угол в мастере, затем ПКМ по блокам. Выбор ограничен по времени; у каждого администратора свой черновик.
2. Назначьте текущую позицию как выход либо оставьте портал без телепортации. Назначение можно убрать отдельной кнопкой.
3. В разделе действий добавьте команды, их отправителя и порядок. Портал может выполнять только команды, без телепорта. Для публикации включённого портала нужен выход или хотя бы одно действие.
4. Настройте доступ, эффекты и название, затем проверьте предпросмотр и опубликуйте.

Доступ: включение, дополнительное право, игровые режимы, задержка повторного входа, подготовка в тиках, запрет боя и транспорта. Общие разрешённые/запрещённые миры и состояния задаются в `modules/portal/portal.yml → access`.

Эффекты: DUST, END_ROD, PORTAL, REVERSE_PORTAL, ENCHANT или SOUL_FIRE_FLAME; HEX-цвет для DUST, шаг частиц, контур или заполнение. При публикации плоскость постепенно заполняется снизу вверх. В конфиге задаются дальность показа, период, время анимации и бюджеты частиц на портал/игрока. Область не заполняется сущностями и не загружает чанки ради эффекта.

Действие-команда задаётся без `/`; `{player}` заменяется настоящим именем входящего игрока. Корень должен быть явно указан в `allowed-player-commands` либо `allowed-console-commands`. Список консольных команд по умолчанию пустой. Команда от игрока исполняется с его правами; OP ему не выдаётся. Очерёдность действий редактируется в диалоге.

Активация происходит на входе в область. Движение внутри не повторяет команды. Выход до конца подготовки отменяет запуск; перед запуском повторно проверяются доступ, ревизия портала и положение игрока. Кулдаун хранится отдельно для каждой пары игрок/портал в памяти; после перезапуска начинается заново.

Определения (`portal`) и изменённые черновики (`portal-draft`) хранятся в SQLite, названия — ключами `lang.yml`. `/портал отмена` удаляет черновик; повторный мастер позволяет продолжить сохранённый. Старые порталы из документов `place` мигрируются один раз по ID; исходные записи остаются в базе. Старый портал без назначения импортируется отключённым.
