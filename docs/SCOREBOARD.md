# Табло (scoreboard)

Модуль `scoreboard` показывает боковое табло. Личного каталога строк больше нет: сервер задаёт
**именованные табло**, игрок видит первое из них, чьё условие выполнено. Всё табло рисуется на
одной доске с TAB, поэтому второго бокового табло в TAB нет.

## Что показывается

1. **Временное табло** другого плагина (`ScoreboardService`, например арена или событие). Оно важнее
   всех именованных и не зависит от личного выключения, если `scoreboard.overrides.allow-forced: true`.
2. **Именованное табло** — первое по порядку в `scoreboard.yml → scoreboards`, у которого
   `display-condition` выполнено. Пустое условие означает «всегда».
3. Ничего, если игрок выключил табло (`/le scoreboard toggle`), либо если модуль выключен, либо если
   игрок не прошёл авторизацию или не имеет доступа к модулю.

Сразу после входа табло не показывается первые `scoreboard.delay-on-join-ms` миллисекунд (по умолчанию
1000): клиент успевает завершить вход.

## Настройка

```yaml
# modules/scoreboard/scoreboard.yml
scoreboards:
  kingdom:
    title: <gold>Королевство
    display-condition: ''
    lines:
    - '<gray>Путник: <white><player>'
    - '<gray>Клан: <white><clan>'
  pvp:
    title: <red>Бой
    display-condition: in-combat
    lines:
    - '<gray>Противник рядом'
```

- `title` — MiniMessage и плейсхолдеры `%...%`.
- `lines` — от 1 до 15 строк, длина строки не ограничена. Пустая строка даёт отступ.
- `display-condition` — имя условия из `modules/tab/tab.yml → conditions`. Условия задают правила
  «скрывать при AFK», «скрывать в бою», «только в этом мире», «только в этом режиме» и «только с правом»:
  например, `%loveessential_afk% == true` или `permission:loveessential.vip`.
- В строках работает тег `<condition:имя>`: он выводит текст `yes` или `no` из того же условия.

Прочие параметры `scoreboard.yml`:

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `enabled` | `true` | модуль |
| `refresh-ticks` | `20` | обновление, тики (2–1200) |
| `default-enabled` | `true` | показывать табло игрокам, которые ничего не меняли |
| `delay-on-join-ms` | `1000` | задержка первого показа после входа (0–60000) |
| `show-seconds` | `60` | сколько длится `/le scoreboard show` (1–3600) |
| `overrides.allow-forced` | `true` | временные табло видны при личном выключении |
| `overrides.max-seconds` | `600` | максимум длительности временного табло |
| `overrides.per-player-limit` | `8` | одновременных временных табло на игрока |

Значения в конфиге проверяются при загрузке: пустой заголовок, больше 15 строк, повторный или неверный
идентификатор отклоняются с ошибкой, и табло продолжает работать на прежней конфигурации.

## Команды

- `/le scoreboard` или `/le scoreboard toggle` — включить или выключить табло для себя. Выбор запоминается.
- `/le scoreboard show <табло> [игрок]` — показать именованное табло на `show-seconds`. Для другого игрока
  нужен `loveessential.admin`.
- `/le scoreboard edit` — редактор для администратора: список табло (по 28 на страницу), добавление,
  заголовок, условие показа, строки, удаление. Кнопки переключают модуль и открывают правила модуля.

## Миграция

Прежний личный каталог (восемь слотов, варианты, пресеты, выбор игрока и импорт из LoveTweaks) удалён.
При первом запуске старый `scoreboard.yml` копируется в `scoreboard.yml.pre-named.bak`, и включаются
табло по умолчанию. Личные выборы игроков из SQLite (`scoreboard-player`) не читаются. Сохраняется только
личное включение и выключение, оно хранится в `scoreboard-visibility`.

Двойной показ с LoveTweaks по-прежнему предотвращается: `TweaksScoreboardBridge` выключает табло LoveTweaks,
а команда `/scoreboard` LoveTweaks обрабатывается модулем: без аргументов переключает табло, `edit` открывает редактор.

## Ограничения

- Ширина строк и выравнивание заголовка не центрируются автоматически.
- Порядок в клиенте и визуальное поведение (мерцание при смене строк, отображение 15 строк) проверяются на живом сервере.
