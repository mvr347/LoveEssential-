# Потоки, жизненный цикл и удержание памяти

Проверка относится к исходникам LoveEssential и его аддона Love Integration.
Она включает чтение асинхронных цепочек и регрессии MockBukkit на Java 25.
Это не трассировка всех Bukkit-вызовов на реальном сервере.

## Границы исполнения

| Путь | Что остаётся в основном потоке | Что выполняется фоном |
| --- | --- | --- |
| Запуск | onEnable, setup, создание сервисов, регистрация команд/слушателей, startServices | Загрузка и миграция файлов, SQLite; результаты приходят через MainThread |
| NPC | Чтение мира для снимка, сущности, повороты, экипировка, голограммы, применение пути | Поиск пути по готовому снимку в ограниченном CPU-пуле; чтение/запись SQL |
| TAB, scoreboard, GUI | Тики, интеграции, текст с данными живого игрока, слоты, клики, навигация | Хранение настроек и публикация файлов |
| Профили и приватность | Статистика Bukkit, снимки игрока, показ GUI, применение сохранённых флагов | SQLite и разбор сохранённых простых данных |
| Чат | Применение введённого текста и действия визарда через MainThread | Отмена AsyncChatEvent, чтение concurrent-реестра запросов, извлечение текста события |
| PAPI | Получение живых помощников revive и рендер text_* с обращениями к интеграциям | Чтение опубликованных неизменяемых scalar-снимков и готовых текстов |
| MOTD | Windows.refreshMotd строит Component | Ping читает volatile immutable Component |
| Остановка | Закрытие GUI, эффектов, сущностей и слушателей; отмена MainThread-запросов | Завершение принятого I/O и SQLite; новые задачи не принимаются |

MainThread.require установлен на запуск/завершение плагина, setup/startServices,
жизненный цикл revive и получение живых NPC-сущностей. module(name, enabled),
вызванный фоном, возвращается через MainThread, прежде чем читать ревизии и
менять состояние модулей. ready публикуется как volatile.

## Найденные проблемы и исправления

1. Revive.values(UUID) вызывался PAPI из async-чата и получал живого помощника через
   Bukkit. Теперь значения публикуются основным тиком в immutable Map; фоновое
   чтение не обращается к игрокам и не читает изменяемые поля состояния.
2. PAPI text_* мог рендерить данные игрока и вызывать чужие API фоном. Теперь запрос
   из async читает кэш и ставит обновление в MainThread без блокирующего ожидания.
   Первый холодный async-запрос возвращает пустую строку; после серверного тика
   доступен результат. При обновлении старое значение остаётся до готовности нового.
   Имена плейсхолдеров и шаблоны не изменены.
3. При быстром перезаходе /display мог загрузить старые флаги до завершения записи
   предыдущей сессии. Загрузка теперь ждёт её tail; token сессии и экземпляр Player
   запрещают применение старого ответа и повторную загрузку вышедшего игрока.
4. Карты фильтра GUI сохраняли UUID после выхода. Фильтр и флаги маршрутизации
   очищаются на quit/close. Закрытие меню при stopping не создаёт новую задачу Bukkit.
5. Исключение в close одного модуля прерывало закрытие SQLite/I/O. Каждый модуль
   закрывается отдельно с диагностикой; вложенный finally завершает I/O, SQLite и
   отсоединяет MainThread даже при ошибке другого компонента. Тест воспроизводит
   исключение эффекта видимости в Gameplay.close, проверяя закрытый Hikari pool.

6. Контрольный тест подтвердил, что административный GUI оставался открыт после
   отключения и снятия его click-listener. Теперь все открытые GuiLayout этого
   плагина закрываются на main thread до снятия обработчиков; обычные сундуки
   игроков не закрываются. Это также освобождает Inventory/holder и его callbacks.

## Память и ограничения

- Двенадцать значений /display больше не собираются заново при каждом PAPI-запросе.
  Одна immutable Map опубликована на состояние и заменяется при изменении флагов;
  общий вариант «всё показано» разделяется. Тест проверяет идентичность снимка и
  неизменность старого после переключения.
- Кэш текстовых PAPI-результатов ограничен весом 4 МиБ и простоем 5 минут. В ключах
  только UUID и имя параметра; Player, World и Inventory в нём не сохраняются.
  Одновременно допускаются не более 64 обновлений, одинаковые запросы объединяются.
  Публикация результата синхронизирована с закрытием, чтобы не наполнить кэш снова.
- API-кэш профилей уже ограничен весом (по умолчанию 16 МиБ), временем простоя
  5 минут и 64 незавершёнными чтениями; это сохранено.
- Сохранены лимиты I/O 8 + 256, SQLite и NPC, а также ограниченные кэши голов и
  истории меню. Для callback профиля переиспользуется один MainThread-dispatcher.

## Регрессии и пределы проверки

Строгий PlayerMock запрещает читать имя живого игрока из фонового потока. Тесты
проверяют revive и холодный/готовый text_* из virtual threads, закрытый текстовый
кэш, запрет off-thread lifecycle/entity API, переключение модуля фоном, отменённый
main-call без позднего Bukkit-действия, уход игрока и очистку GUI, быстрый повторный
вход при заблокированном писателе SQLite, переиспользование display-снимков,
отключение с открытым меню и отказ одного close.

На Paper/Purpur не выполнялись AsyncCatcher-проверка с реальными интеграциями,
профиль JFR/heap после GC и нагрузка 100 игроков/NPC. Снижение объёма heap или времени
тика в процентах не заявляется. Потоковые контракты API сторонних плагинов требуют
проверки именно с установленными на сервере версиями.
