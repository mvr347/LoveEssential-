# Посадка, следы и голограммы

[Главная](../README.md) · [Команды](COMMANDS.md) · [Права](PERMISSIONS.md)

## Чат и дома

`/sethome` сохраняет единственную точку и отвечает «Точка дома установлена». Ошибки лимита, территории и базы по-прежнему показываются. Тексты и оформление уведомлений находятся в локальных `messages` конфигов модулей и `gui.yml`: `chat.prefix`, `chat.saved`, `chat.*`, `comfort.*`, `holo.*`.

Запрос телепорта показывает направление и кнопки `[Принять]` / `[Отклонить]`. Кнопка привязана к конкретному запросу: старое сообщение не отменяет новый запрос. ЛС содержит `[Ответить]`, сообщение о перемещении — `[Назад]`, публикация NPC — `[Редактировать]`. Ввод в чат отменяется существующей кнопкой `[ОТМЕНИТЬ ВВОД]`. Ошибка формата предлагает `[Команды]`.

## Sit, ride, hat

- `/sit`: сесть на поверхность под ногами. Повтор команды или Shift — встать. Высота вычисляется по collision shape блока, включая половинные плиты и ковры. На обычные блоки можно сесть командой.
- ПКМ пустой основной рукой по ступеням, плитам или ковру: сесть на блок. Shift пропускает посадку. Проверяются место для тела, занятость и территория.
- `/ride [игрок]`: без аргумента выбирает живую цель по направлению взгляда; с именем — указанного игрока в пределах дальности. Проверяются прямая видимость, территория, свободная цель, авторизация, бой и отсутствие цепочки транспорта. Посадка на игрока включается через `player-riding-enabled` в модуле. Носитель может снять пассажира командой `/eject`, `/сбросить`, `/ride eject` или ударом по своему пассажиру; такой удар отменяет урон. Повтор `/ride` снимает самого ездока.
- `/hat`: ровно один предмет из основной руки меняется местами со шлемом. Стопка не расходуется и не разделяется. Проклятие несъёмности учитывается в survival.

`/lay`, `/лежать`, `/лечь` переключают позу лёжа. Смена позы сервером не завершает /lay: поза повторно удерживается до явного выхода. Повторная команда, приседание, урон, телепорт, выход и исчезновение опоры восстанавливают исходную позу.

`modules/sitride/sitride.yml`: `click-to-sit`, `ride-range`, `player-riding-enabled`, общие ограничения `access`. При отключении модуля, выходе, телепорте, уроне и исчезновении опоры сиденье очищается. Временные стойки не сохраняются в мире.

## Следы

`/traces [on|off]` переключает личный выбор, сохранённый в SQLite. Модуль включается через `/le module traces enable` или главное меню. В исходном конфиге он выключен.

Следы чередуют левую и правую ногу, учитывают высоту поверхности и ограничены расстоянием шага и временем. Повороты на месте, полёт, транспорт, плавание и vanish не создают следов. Частицы видят авторизованные игроки поблизости, которые видят самого игрока. Это короткие частицы, без сохраняемых сущностей или изменений блоков.

`modules/traces/traces.yml`: `default-enabled`, `stride` (блоки), `interval-ms`, `view-distance`, `color` (шесть цифр RGB). Настройки имеют подписи и описания в GUI.

## Голограммы

1. `/le hologram` → «Добавить» или `/hologram create [первая строка]`. ID назначается автоматически. Без текста откроется понятный запрос ввода с отменой.
2. Нижняя строка появляется на два блока выше игрока; добавленные строки располагаются выше, чтобы длинный текст не уходил под землю. Высота создания настраивается в модуле.
3. В редакторе видны текущие тексты и номера строк. ЛКМ открывает редактор строки. Есть кнопки изменения текста, замены предметом, удаления, переноса выше/ниже. Shift+ЛКМ / Shift+ПКМ в списке быстро меняют порядок.
4. «Добавить предмет» копирует предмет из основной руки, не расходуя его. Сохраняются компоненты и метаданные Paper; используется ItemDisplay.
5. Верхние кнопки меняют фон AARRGGBB (`00000000` — прозрачный), тень, интервал и дальность. На кнопке перемещения показаны координаты; обычное нажатие переносит к игроку, Shift+ЛКМ поднимает на 0.25, Shift+ПКМ опускает на 0.25 блока.
6. Нижние кнопки добавляют/удаляют страницы. ПКМ по голограмме переключает страницы отдельно для каждого игрока. Для страницы можно назначить разрешённую команду игрока; `reset` возвращает перелистывание.

Текст поддерживает MiniMessage и плейсхолдеры LoveEssential, например `<player>`, `<nickname>`, `<clan>`, `<papi:...>`. Значения вычисляются для конкретного зрителя. Предметы и страницы хранятся в SQLite, текстовые строки — в `modules/hologram/hologram.yml → messages`. Сохраняйте оба файла при резервном копировании.

Команды: `/hologram edit <id>`, `info <id>`, `addline <id> <текст>`, `move <id>`, `delete <id>`. Удаление требует подтверждения. В старом синтаксисе `create market Текст` слово `market` теперь является частью текста; ID назначается плагином. Старые сохранённые ID остаются доступными.

Старые записи `place/hologram:*` автоматически переносятся в документы `hologram`, позиция поднимается на два блока. После успешного переноса старая запись удаляется, поэтому удалённый объект не восстанавливается при перезапуске.

`modules/hologram/hologram.yml`: лимит определений, высота создания, максимум ближайших голограмм на зрителя и общий бюджет display/interaction-сущностей. До 16 страниц и 32 строк на страницу. Выгруженные чанки не загружаются принудительно; невидимые сущности удаляются. Большое количество зрителей и строк увеличивает нагрузку, поэтому предусмотрены лимиты.

## API магазина и других Love-плагинов

Сервис `HologramService` получается через Bukkit ServicesManager. Чтение и регистрация обработчиков выполняются в основном потоке; `save` и `delete` возвращают futures и сами переключают операции в нужный поток. Запись требует ожидаемую ревизию; `0` создаёт объект. Удаление/повторное создание не сбрасывает версию.

Пример привязки магазина к голограмме, созданной администратором:

```java
var holograms = Bukkit.getServicesManager().load(HologramService.class);
if (holograms != null) {
    var registration = holograms.onClick("holo_ID_из_редактора", (player, id, page) -> {
        // Вызвать собственный API магазина с его проверками доступа.
        player.performCommand("shops");
        return true; // Нажатие обработано; страницу не переключать.
    });
    // В onDisable своего плагина вызвать registration.close() в основном потоке.
}
```

`HologramService.Hologram` содержит позицию нижней строки, страницы, фон, тень, интервал и дальность. `Page` содержит строки и необязательное `Action` из общего движка LoveEssential. `Line` содержит либо ключ локальных `messages`, либо Base64 от `ItemStack.serializeAsBytes()`. Публичное API предназначено для доверенных серверных плагинов; они отвечают за права и правила своего магазина. GUI-команды страниц исполняются от имени игрока и ограничены `modules/npc/npc.yml → actions.allowed-player-commands`; консольные команды не добавлены.

NPC, рецепты, сценарии, диалоги и порталы получают ID автоматически при создании через интерфейс. Явные ID в совместимых командах остаются необязательным способом для интеграций. Имена домов и папок миров остаются пользовательскими именами.

## Служебные команды

Модуль `utilities`: `/heal`, `/feed`, `/fly`, `/speed <0–10>`, `/gamemode <survival|creative|adventure|spectator>`, `/repair`. Действуют на вызывающего игрока. Скорость изменяется для полёта, если игрок сейчас летит, иначе для ходьбы; ремонт затрагивает только предмет в основной руке. Каждой команде нужно собственное право `loveessential.<команда>`; по умолчанию OP.

Посадка и геометрия проверены автоматическими тестами расчёта поверхности; GUI, SQL, миграция и команды — MockBukkit. Визуальное положение персонажа, частицы, ItemDisplay/TextDisplay и взаимодействие в игровом клиенте требуют проверки на Paper/Purpur 26.2+ с Java 25.
