# Пошаговые мастера Love

Обзор исходников на 1 ноября 2026. «Мастер» здесь означает последовательность с понятным текущим шагом,
а не просто редактор с несколькими кнопками. Изменения этого PR касаются порталов и билета Hunt;
остальные пункты ниже — предложения, их реализация не включена.

## Где уже есть

| Плагин и механизм | Как работает сейчас | Что полезно взять |
|---|---|---|
| LoveDuels — арены | `/lda arena wizard [id]`: пять шагов в чате, кликабельные установки спавнов и границ, необязательные зоны, проверка готовности и предпросмотр | Основной образец: короткое объяснение и действие кнопкой прямо в мире |
| LoveShops — торговые точки | `/tradepointadmin create`, затем `wizard set/back/skip/finish/cancel/status`: шесть точек настройки, кнопки чата, итог перед созданием | Явные «Назад» и «Пропустить», обзор выбранной зоны, отдельное завершение |
| LoveEssential — NPC | `NpcWizard`: GUI разделов, ввод отдельных значений в чат, запись маршрута инструментом, черновики SQLite | Сохранение черновика, подтверждение удаления и маршруты; целиком чатовым этот мастер пока не является |
| LoveEssential — порталы | До этого PR — экран разделов и отдельные формы. Теперь семь последовательных шагов в чате | Объединяет пример Duels с сохранением шага, защитой старых кнопок и реестром частиц |

Источники: `LoveDuels/command/LoveDuelsAdminCommand`, `LoveShops/market/wizard/WizardService`
и `PointWizard`, `LoveEssential/wizard/NpcWizard`, `LoveEssential/portal/PortalGuide`.

## Похожие интерфейсы, которые не являются чатовым мастером

- **LoveClans:** `ClanBannerCreationMenu` — компактный редактор создания клана у флага,
  нативный диалог имени/тега и запасной ввод в чат. Полная последовательность шагов отсутствует.
- **LoveContracts:** `ContractCreateGUI` содержит старую механику создания, но `open(Player)` сейчас
  сообщает об отключённой функции. Это не действующий мастер; автоматически включать её не следует.
- **LoveEssential:** путевые столбы, миры, сценарии и диалоги используют формы/редакторы;
  голограммы создаются и затем редактируются отдельными действиями.
- **LoveLeaderboards:** стенд создаётся административной командой с типом, категорией и местом.
- **LoveHunt:** привязка NPC и административное создание охоты имеют собственные команды и меню.

## Куда внедрять в первую очередь

| Приоритет | Механика | Предлагаемые шаги | Зачем |
|---|---|---|---|
| 1 | Путевые столбы LoveEssential | Название → модель из общего каталога → установка и направление → направления поездок → цена/ожидание/доступ → предпросмотр → публикация | Важно видеть модель и точку назначения в мире; цена и доступ не затеряются в формах |
| 1 | Голограммы LoveEssential | Место → текст/предмет → строки → высота и направление → фон/действие → предпросмотр | Сразу видно, где находится текст и что именно произойдёт при нажатии |
| 1 | Стенды LoveLeaderboards | Тип рейтинга → категория → период → позиция → внешний вид → предпросмотр и создание | Убирает необходимость помнить порядок параметров команды |
| 2 | NPC LoveEssential | Имя → тип/скин → позиция → неподвижность/наблюдение/маршрут → действия → публикация | Чатовые кнопки удобны для координат и записи маршрута; точные настройки оставить в GUI |
| 2 | Привязка NPC LoveShops / LoveHunt | Роль → выбор уже существующего NPC провайдера → назначение магазина/охоты → проверка → привязка | Использовать единый NPC LoveEssential через LoveCore, сохранять внешний ключ и не создавать дубликат сущности |
| 2 | Миры LoveEssential | Создать/импортировать/клонировать → имя и источник → проверка каталога/измерения → генерация или параметры → спавн/правила → подтверждение | Для импорта нужна предварительная проверка пути и мира; разрушительные операции требуют отдельного подтверждения |
| 3 | Сценарии LoveEssential | Событие → кого затрагивает → условия → действия → проверка → включение | Подходит для первого входа, выдачи стартового набора и приветственных событий |
| 3 | Заготовки диалогов LoveEssential | Тип окна → заголовок → поля/кнопки → действия → предпросмотр | Создание заготовки можно упростить мастером, сложные формы оставить редактору |

Для игрока создание обычного контракта лучше оставить компактным GUI с реальными предметами.
Не стоит принудительно переносить торговлю, инвентари и выбор ингредиентов в чат: там нужен сам предмет.

## Общие правила хорошего мастера

1. В заголовке видны шаг, общее количество и название операции.
2. Каждая кнопка объясняет действие при наведении. Для ввода указаны формат и пример.
3. «Назад» сохраняет значения. Повторный проход позволяет оставить выбранные точки.
4. Кнопки старого шага и другого игрока не изменяют текущий черновик.
5. Черновик и текущий шаг сохраняются в SQLite; «Сохранить и выйти» позволяет продолжить позже.
6. Выбор позиции и предпросмотр происходят в мире; публикация выполняется отдельно.
7. Ввод команды сохраняет её, а не выполняет. Команды портала проверяются по списку разрешённых корней.
8. Владение вводом координируется: старый мастер не должен забирать текст у нового или отменять его запрос.
9. Частицы с дополнительными данными получают корректные типизированные параметры; тяжёлые эффекты ограничиваются.
10. Тексты, пояснения и названия эффектов задаются непосредственно в GUI-конфиге соответствующего модуля.
