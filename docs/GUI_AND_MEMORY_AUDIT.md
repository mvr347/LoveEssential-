## Исправления

- Ожидающие вызовы основного потока завершаются ошибкой отмены при остановке плагина; проверяется также гонка с планировщиком. Состояния разных загрузок плагина разделяются по идентичности экземпляра.
- SQLite завершает Future отброшенных заданий при принудительном завершении очереди. При штатной остановке сначала выполняются принятые записи. Ошибка отмены не означает откат уже выполнявшейся транзакции.
- API профилей хранит завершённые значения в кэше с весовым лимитом `storage.profile-cache-mib: 16` и сроком простоя пять минут. Одновременных чтений не больше 64; одинаковые запросы объединяются. Отмена одного потребителя не отменяет остальных. Старое чтение не возвращает устаревшее значение в кэш после записи.
- Снимки информации игрока сохраняются с объединением: одна запись выполняется, последнее новое состояние ожидает. Операции с предметами и самостоятельные действия не объединяются.
- NPC получает разрешение на подготовку пути до чтения блоков. По умолчанию допускается восемь заданий, сбор распределяется между тиками с бюджетом 2 мс. Внешний синхронный обработчик территории нельзя прервать посреди одного вызова; бюджет проверяется между ячейками. Bukkit API не переносится на фоновые потоки.
- Неизменяемый снимок проходимости использует BitSet; A* работает в ограниченном пуле. Результат применяется только к актуальному экземпляру NPC. Задержки ошибок очищаются при удалении и остановке.
- Текстуры голов кэшируются ограниченно; игрок получает отдельный ItemStack. Повторный рендер профиля меняет только отличающиеся слоты, голограммы не отправляют повторно одинаковый текст.
- Поставляемые шаблоны конфигурации разбираются один раз и повторно используются при reload, с отдельными копиями изменяемых значений.
- Нативные диалоги ограничены по количеству и времени жизни. Навигация GUI очищается при закрытии/выходе; история ограничена 16 переходами.

Числовые старые ID не перекрываются новыми номерами в API: точный технический ID имеет приоритет. Команды разрешают видимый номер в исходный ID до выполнения операции.

## Замер структуры снимков NPC

Java 25; 64 независимых полностью проходимых снимка, каждый 49 × 49 × 9 = 21 609 ячеек. Перед замером — 16 прогревочных построений. Выделения измерены ThreadMXBean, удерживаемый heap — после принудительного GC. Оба запуска записаны в JFR.

| Показатель | До: множество координат | После: BitSet |
| --- | ---: | ---: |
| Выделено при построении 64 снимков | 163 492 136 байт | 357 160 байт |
| Изменение удерживаемого heap | 44 313 768 байт | 203 216 байт |

Это изолированный замер представления снимка. Он не измеряет весь плагин, чтение блоков, обращения к LoveCore или TPS. Число 64 выбрано для измерения структуры; новый рабочий лимит — восемь заданий.

Воспроизведение из корня репозитория:

```bash
JAVA_HOME=/path/to/jdk-25 tools/benchmarks/run-snapshots.sh /tmp/loveessential-memory
```

Скрипт использует старую реализацию из коммита `163f5279f10582418727c755f005edbea4278f34` и текущую реализацию, сохраняет JFR и числовые результаты. Результаты могут отличаться между JVM и сборщиками мусора.

## Проверки поведения

Регрессионные сценарии покрывают переполнение/остановку хранилища, сохранение между перезапусками, устаревшие ревизии, ограничение веса кэша и объединение запросов. GUI проверяются через MockBukkit, включая 50 циклов «профиль → настройки → назад → закрыть» с проверкой освобождения сессий. Сохраняются проверки приватности, офлайн-профилей, стартового набора и переноса предметов в административном просмотре.

Живой сервер Paper/Purpur с 100 игроками и 100 NPC не предоставлен; такой прогон и визуальная проверка клиентом Minecraft не проводились. Замер структуры и MockBukkit не заменяют эти проверки. Обнаруженные при статическом просмотре потенциальные проблемы не объявляются воспроизведёнными эксплойтами.

Итоговая проверка: Java 25, Paper API 26.2, Maven verify — 247 тестов, 0 failures/errors/skips (после слияния с main). Проверены 56 YAML на уникальные ключи, ссылки документации и git diff --check. JFR записан для исходного и итогового тестовых сценариев; числовое сравнение выше относится только к изолированному одинаковому сценарию снимков.

## Раскладка меню (gui_gen v2.1)

Правила раскладки проверяет `GuiLayoutAuditTest` вместе с `GuiRules`: администратор открывает каждое корневое меню, а затем переходит по каждой кнопке на два уровня вглубь. Проверяется размер (27/36/45/54), отсутствие пустых слотов в Header и Footer, стекло только в рамке, Row1 из стекла при размере от 45, слоты 1 и 8 из стекла, центрирование кнопок управления в слотах 2–7, пустые боковые стенки и положение Close/Back. Нарушения, найденные этим аудитом: стеклянные плитки ингредиентов в редакторе крафта, две кнопки в нижнем ряду стартового набора, управляющие кнопки в Footer редактора голограмм. Все исправлены; редактор голограмм теперь делится на редактор строк и менеджер страниц. Close распознаётся по метке `loveessential:close`, а не по тексту.

После аудита выполнена [доработка GUI и схемы конфигурации 6](GUI_CONFIGURATION_V6.md): полный прогон после слияния с main — 247 тестов без ошибок и пропусков. Приведённые выше JFR и замер снимков относятся к исходному аудиту, повторного измерения всего плагина это дополнение не заявляет.
